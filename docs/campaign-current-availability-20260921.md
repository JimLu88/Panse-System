# 原活动续接：当前可用性与历史回执分开

修复两个代码原因：整批不完整曾吞掉独立商品的真实OFF证据；旧优惠成功回执被当成当前仍有效，阻挡新的精确窗口。

`campaign_recorded_sku_state`按唯一商品、唯一全属性/编码/价格/库存匹配及显式关闭开关提取事实。兄弟商品超时不抹去已核行；重复/冲突、缺行、零库存均不能推断关闭。原job、文件、视频校验继续，录屏缺帧如实保留。

`campaign_discount_availability`使用原请求、固定Web Agent读回、数据库job与文件哈希验证当前优惠状态。旧窗口成功/unknown账本不改；只有原请求目标窗口、明确旧优惠ID、用户已撤出/暂停的背景及无额外筛选的精确空结果，才不再以旧优惠阻挡新窗口。`not_found`不改名为deleted/paused，不证明金额、报名或新优惠成功。实际paused须明确重启控件和匹配窗口。事实过时、身份/文件改变、范围不全仍阻挡。

仅03原连续请求续接，单品立减→超级立减→同窗口主题活动顺序不变。该原请求只包含前两步；国庆仍独立待后续。已报商品继续通过previously_enrolled跳过重复signup；新优惠必须新终态。

本轮ERP相关136项回归、新增来源边界20项通过（部分测试重合，不合并宣称156个不同测试）。真实只读查得3旧优惠无记录、19条SKU关闭事实；原请求prepare得到29件可续接，1条SKU保持未知。不等于29件已成功。

影响审查：生成文件、旧优惠重叠检查、报名防重放、异常收口；价格/首次基线/库存/订单/财务/工厂表不改。关系CLI指出新增脚本未建模，关系图现有“商品核对/固定程序边界”表达不能当新来源分支已全覆盖。此修复是本机执行脚本安装，非NAS前后端重新发布。
