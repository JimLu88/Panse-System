# 群晖统一发布流程

2026-07-21 起，畔色 ERP 生产发布只有一个正式入口：`scripts/deploy_release_nas.sh`。

## 为什么必须统一发布

群晖部署目录没有 Git 仓库。API 是 Python 镜像，Web 是编译后的静态文件镜像；两者可以独立运行，也就可能被不同机器、不同提交分别覆盖。仅查看 `/api/version` 只能证明后端版本，不能证明浏览器中的前端版本。

统一发布把以下条件设为硬门槛：

1. `HEAD` 必须与 `origin/main` 完全一致，禁止部署未 push 或落后的代码。
2. 工作区不能有未提交的已跟踪修改。
3. API 和 Web 都从同一个完整 Git commit 构建。
4. 上传新镜像前，给 NAS 当前镜像打带时间戳的回滚标签。
5. API 用 `/api/version`，Web 用 `/build-version.json`，两者必须等于预期 commit。
6. 数据库必须在 Alembic `(head)`，四个生产容器必须运行。
7. 在线 Web bundle 必须包含活动生命周期、定制报价双口径和真实 BOM 核对界面。

## 正式发布

必须在 Git Bash 中运行。不要用 PowerShell 传 Docker 二进制镜像流。

```bash
git switch main
git pull --ff-only
bash scripts/deploy_release_nas.sh
```

脚本顺序：

1. 构建并验证 API 内容指纹；
2. 备份 NAS 旧 API 镜像，传输并启动新 API；
3. 重启 Web，使 nginx 重新解析 API 容器地址；
4. 构建带提交标记的 Web；
5. 备份 NAS 旧 Web 镜像，传输并启动新 Web；
6. 运行全套只读验收。

## 只读验收

```bash
bash scripts/verify_release_nas.sh
```

验收不会写业务数据，检查：

- `/api/health` 与 `/api/ready`；
- API/Web 完整 Git commit 一致；
- `/api/campaigns` 与 `/api/customization/v2/quote-both` 已注册；
- 在线 JS 包含三个目标界面；
- `alembic current` 为 `(head)`；
- `api/web/db/backup` 四容器运行。

## 回滚

发布日志会打印本次保留的两个标签，例如：

```text
panse-system-api:rollback-20260721-013000
panse-system-web:rollback-20260721-013500
```

只有在新版本验收失败且无法立即修复时才回滚。API/Web 要成对恢复到同一批次，并再次运行验收；数据库迁移通常只向前，不得擅自 downgrade。回滚操作会影响生产服务，执行前先确认确切标签和当前容器状态。

## 禁止事项

- 禁止从未 push 的本地提交部署。
- 禁止只部署 API 或只部署 Web 作为日常发布方式。
- 禁止用 API 版本标签推断 Web 已更新。
- 禁止在 NAS 镜像里直接改代码后长期运行。
- 禁止给 LAN Web compose 加 `--remove-orphans`。
- 禁止未经确认执行 Alembic downgrade 或删除生产 volume。
