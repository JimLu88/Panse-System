## 1. 目标与总体思路

**目标**：在用户搜索/询问「实木家具」「实木餐桌推荐」「小户型原木风家具」等问题时，让「畔色木作」出现在答案里——既包括传统搜索引擎，更包括 AI 答案引擎（豆包、Kimi、DeepSeek、文心/百度AI搜索、ChatGPT、Perplexity、Google AI Overviews）。这正是项目名里的 **AEO（Answer Engine Optimization，答案引擎优化）**。

**AEO 的本质**（2026 年业界共识）：AI 引擎通过训练语料与实时检索形成「品牌偏好」——当一个品牌在多个来源中持续与某类话题（实木家具、北欧原木风、高性价比定制）共同出现，模型就更倾向把它当作答案。因此策略是两条腿：

- **腿 1：自有内容阵地**（官网/内容站）——做严格的 AEO 技术优化，**可 100% 全自动**，是整个系统的核心资产。
- **腿 2：平台渠道分发**（公众号/小红书/知乎/抖音）——同一内容多平台一致出现，强化 AI 引擎的「共现信号」。各平台自动化可行性差异大，见 §4 分级。

**全自动的边界（诚实结论，先说清楚）**：

| 环节 | 能否全自动 |
| --- | --- |
| 内容站生成、发布、搜索引擎收录推送、AI 引擎效果监测 | ✅ 完全自动 |
| 微信公众号发文 | ✅ 完全自动（需企业认证主体，见 §4） |
| 小红书、抖音、知乎发布 | ⚠️ 只能半自动（官方 API 不对普通账号开放；浏览器自动化=封号风险，不做） |

第一阶段的全自动闭环 = **内容站 + 公众号 + 收录推送 + 效果监测**；小红书等做成「素材自动备好、你一键转发」的半自动并行线。

## 2. 文案可编辑化改造（需求 1 前置）

现状问题：大量文案写死（hardcode）在代码里。目标：**代码只管流程，所有内容来自可编辑的内容库**。

### 2.1 内容库设计（三层）

```
content/                      # 全部为 repo 内可编辑文件，git 版本控制
  brand/
    profile.yaml              # 品牌档案：品牌故事、定位、口吻(tone)、目标人群、禁用词
    facts.yaml                # 产品事实表：每个产品的材质/尺寸/价格区间/工艺/交期
                              #   ——AI 生成内容时唯一允许引用的“事实源”，杜绝编参数
  templates/
    article.md.j2             # 文章模板（Jinja2 占位符：{{brand}}/{{product}}/{{faq}}）
    faq.md.j2 / xhs_card.j2   # 各渠道模板
  topics/
    keywords.yaml             # 选题关键词库（核心词/长尾词/问句），含优先级与已用记录
  published/                  # 流水线产出归档（只增不改）
```

### 2.2 改造原则

- **格式选 YAML/Markdown 而非数据库**：你可以用任何编辑器改，git 能追溯每次修改，Claude 也能直接帮你批量改写；程序启动时加载 + 文件监听热更新（或每次任务运行时重读），改完即生效、无需重启。
- 代码中每一处写死的字符串，按「品牌事实 → `facts.yaml`、口吻话术 → `profile.yaml`、结构骨架 → 模板」三类归位；找不到归属的视为流程文案（日志、报错），留在代码里。
- 后续如需图形界面，再加一个极简 Web 编辑页（FastAPI + 单页表单）——Phase 4 可选项，不阻塞主线。

> 具体改哪些文件、抽多少处字符串，待 Phase 0 代码审查后在附录列清单。

## 3. 全自动流水线架构（需求 1b/1c 核心）

整条流水线是一个**状态机**，每篇内容是一条记录，逐步推进，任何一步失败自动重试、重试耗尽则跳过并记录，**不需要人守着**：

```
selected → generated → checked → rendered → scheduled → published → submitted → measured
 选题        AI生成      自动质检    渲染排版     排期        发布       收录推送     效果回流
```

### 3.1 各步骤职责

1. **选题（selected）**：从 `topics/keywords.yaml` 取未用/到期复写的关键词，结合产品事实表组合成具体选题（如「胡桃木餐桌怎么保养」）。每周节奏可配置（建议 3~5 篇/周，**质量优先于数量**——AI 引擎对内容农场会降权）。
2. **生成（generated）**：调 Claude API（项目里复用 Panse-System 的 `ai_provider` 模式：key 存配置、prompt 缓存品牌档案），输入=品牌档案+事实表+选题+模板结构，输出=问答式文章（H2 用问句、首段 2~3 句直接给答案——这是被 AI 引擎引用的关键结构）。
3. **质检（checked）**，全自动三道闸：
   - **事实闸**：文中出现的数字/材质/价格必须能在 `facts.yaml` 中找到出处，否则打回重写（防 AI 幻觉编参数）；
   - **合规闸**：广告法极限词过滤（最/第一/顶级/100%…词表可编辑），命中即自动替换或重写；
   - **质量闸**：用小模型给「品牌口吻一致性 + 与既有文章查重」打分，低于阈值重写，连续 3 次不过则标记 skip 并记入日报。
4. **渲染（rendered）**：同一内容渲染成多渠道格式——内容站 HTML（含 JSON-LD 结构化数据）、公众号图文 HTML、小红书图文卡片素材包。
5. **排期/发布（scheduled/published)**：
   - 内容站：写入静态站点目录 → `git push` 触发自动部署（零成本、零服务器）；
   - 公众号：`draft/add` 存草稿 → `freepublish/submit` 发布（异步，回调确认结果）；
   - 半自动渠道：素材包落盘 + 飞书机器人推给你（一键复制粘贴）。
6. **收录推送（submitted）**：sitemap 自动更新 + **IndexNow** 推送 Bing/360 等、百度站长 API 推送、Google 走 sitemap；同时维护 `llms.txt` / `llms-full.txt`（对 AI 爬虫的内容索引，实测可显著提高抓取率）。
7. **效果回流（measured）**：见 §5，结果反哺选题优先级。

### 3.2 调度与可靠性（复用 Panse-System 成熟模式）

- **调度器**：APScheduler 定时任务（与 Panse-System `scheduler.py` 同模式）：每日选题→生成→质检；按排期表发布；每周一跑效果监测；每天发飞书日报。
- **状态表**：SQLite 即可（单机、无并发压力）：`content_items`（内容主表+状态机字段）、`pipeline_runs`（每步执行记录/耗时/错误）、`channel_posts`（每渠道发布凭据与回执）、`aeo_metrics`（监测结果）。
- **失败处理**：每步独立重试（指数退避 3 次），耗尽→标记 failed + 飞书告警，**不阻塞其他内容**；进程级用看门狗（同 Panse-System `system_monitor.py` 思路）。
- **人工参与度三档**（配置项，默认 b）：
  a. 纯全自动，只发周报；
  b. 全自动 + 飞书每日摘要（今天发了什么、监测到什么）；
  c. 发布前飞书卡片确认（保险模式，点一下才发）——前两周建议用 c 观察质量，确认后切 b。

## 4. 渠道矩阵与自动化可行性（已查证）

| 渠道 | 自动化程度 | 关键事实 | 前期准备 |
| --- | --- | --- | --- |
| **自有内容站** | ✅ 全自动 | 静态站（Astro/Hugo）+ Cloudflare Pages/GitHub Pages 免费托管；AEO 技术全套：FAQPage/Product/Organization JSON-LD、llms.txt、sitemap、问答式结构 | 买域名；如要百度收录好需国内备案（见 §6 取舍） |
| **微信公众号** | ✅ 全自动 | 官方 API：草稿箱 `draft/add` → `freepublish/submit`；**2025-07 起个人主体/未认证企业号的发布接口权限已被收回** → 必须企业认证主体；发布是异步任务，平台审核可能拒绝，需处理回调 | 企业认证公众号 + 开发者配置（IP 白名单、token） |
| **小红书** | ⚠️ 半自动 | 发布 API 仅对审核通过的品牌/服务商合作方开放，普通开发者申请门槛高；第三方“自动发布”工具多为浏览器模拟，**违反平台规则、封号风险高，本方案不采用** | 注册企业号；流水线自动产出图文素材包+文案，飞书推送一键转发；中期可尝试申请开放平台权限 |
| **抖音** | ⚠️ 半自动 | 开放平台有视频发布接口但需企业资质+权限审批；且视频生产本身需要素材 | 先做图文转视频素材半自动；不作为第一阶段重点 |
| **知乎** | ⚠️ 半自动 | 无开放发布 API；但知乎问答是国内 AI 引擎检索的重要语料源，**对 AEO 价值高** | 流水线为目标问题自动起草回答，人工粘贴（每周 1~2 条即可） |
| **搜索引擎收录** | ✅ 全自动 | IndexNow（Bing/360/Yandex）、百度站长普通收录 API、Google sitemap | 各站长平台注册一次、拿 key |
| **AI 引擎监测** | ✅ 全自动 | 见 §5 | 各 AI 平台 API key |

## 5. AEO 效果监测（全自动 KPI）

没有度量的推广是盲跑。每周自动执行：

1. **提问集**：维护 30~50 个目标问题（`topics/eval_questions.yaml`，可编辑），如「实木餐桌什么牌子性价比高」「畔色木作怎么样」「原木风家具品牌推荐」。
2. **批量询问**：对所有可 API 调用的 AI 引擎（DeepSeek、Kimi、豆包、通义、Claude、OpenAI——key 配置即用，缺谁跳过谁）逐题提问。
3. **判定与记录**：自动检测回答中是否提及「畔色/孚格/品牌站点域名」，存 `aeo_metrics`：提及率、首次提及日期、引用来源。
4. **趋势报告**：飞书周报 + 内容站后台页出曲线。提及率就是这个项目的北极星指标（业界经验：内容上线后 2~6 周可看到首批引用信号）。
5. **回流**：哪些问题已被覆盖、哪些长期空白 → 自动调高空白选题的优先级。

## 6. 你需要做的一次性前期准备（之后程序自跑）

按优先级排序：

1. **域名**：给品牌内容站买一个域名（如 `pansemuzuo.com` 之类）。**关键取舍**：
   - 国内服务器+备案 → 百度/360 收录好，但备案要 2~4 周；
   - Cloudflare Pages 免备案 → 上线即用，Google/Bing/海外 AI 引擎友好，百度收录较弱。
   - **建议**：先 Cloudflare Pages 立刻上线跑通全链路，备案完成后再迁回国内双线。
2. **微信公众号企业认证**（服务号或订阅号均可，主体必须是企业并完成认证）+ 在公众平台开通开发者权限、配置 IP 白名单。
3. **AI API key**：至少一个生成用（建议 Anthropic 或通义/DeepSeek，复用 Panse-System 已有的密钥管理经验）+ 监测用的国内引擎 key（DeepSeek/Kimi/豆包，按量付费、用量很小）。
4. **品牌资料包**（一次填好 `content/brand/`，之后随时可改）：品牌故事 500 字、每个产品的事实参数（材质/尺寸/价格区间/工艺/交期）、20~50 张实拍图、想强调的卖点与禁说的词。
5. **站长平台注册**：百度站长、Bing Webmaster（顺带拿 IndexNow key）、Google Search Console，各绑定域名一次。
6. **运行环境**：可直接复用 Panse-System 那台 Windows+Docker 主机，加一个 `aeo` 服务容器即可（资源占用很小）。
7. （半自动渠道，可延后）小红书企业号、知乎账号、抖音企业号。

## 7. 实施路线图

- **Phase 0 — 接入与审查**（1 个会话）：把 panse-aeo 加入 Claude 环境 → 全量代码审查（结构/依赖/安全/写死文案清单）→ 审查结论与改造清单回填本文档附录。
- **Phase 1 — 内容库与站点骨架**：写死文案抽离到 `content/`（§2）；静态站搭建 + JSON-LD/llms.txt/sitemap 全套 AEO 基建；Cloudflare Pages 自动部署；手工触发跑通「一篇文章从生成到上线」。
- **Phase 2 — 流水线全自动**：状态机 + 调度器 + 三道质检闸 + 失败重试 + 飞书日报；以「发布前确认」模式（§3.2 档 c）试运行两周。
- **Phase 3 — 渠道接入**：公众号 API 自动发文；IndexNow/百度推送;切换到全自动档 b。
- **Phase 4 — 监测与优化**：AI 引擎提问监测 + 周报曲线 + 选题回流；半自动渠道素材包；（可选）Web 内容编辑页。

每个 Phase 都是可独立验收的：Phase 1 结束你能看到一篇真实上线的文章；Phase 2 结束系统能无人值守跑一周；Phase 4 结束你每周只看一份飞书周报。

## 8. 风险与红线

1. **AI 幻觉**：生成内容里的产品参数必须来自 `facts.yaml`，质检闸强制校验——宁可少写一个数字，不编造一个数字。
2. **广告法**：极限词自动过滤（词表可编辑），公众号平台审核被拒会走回调自动重写重发。
3. **平台规则**：不做任何浏览器模拟批量发布（小红书/抖音封号红线）；半自动渠道保持「人发」。
4. **内容农场反噬**：频率克制（每周 3~5 篇）、每篇必须有事实表支撑的独特信息，避免被 AI 引擎判为低质来源。
5. **密钥安全**：所有 key 走环境变量/加密配置，`.gitignore` 已确认覆盖 `.env`；仓库保持私有。
