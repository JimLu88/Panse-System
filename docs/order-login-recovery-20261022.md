# 订单自动推送登录恢复

2026-10-22 18:00和19:17的取数均因session_expired结束，18:30推图因无当日新数据跳过；不是定时器未触发。旧分类器把“登录已失效”当未知故障继续重试。扫码入口只保存会话，订单任务没有消费该结果恢复等待链路。

修复：订单登录异常归为等待人工输入，通知给出“扫码→店铺后台扫码”，暂停无效业务重试。既有18–23点补跑任务先核原导出回执；仅接收故障后、当天、shop平台、success状态、带job与request_key的登录记录，行锁并持久消费一次后复用当日批次续跑。登录入口仍只登录，不负责发送。其他平台、旧登录、未来时间、unknown、重复登录凭证不能放行。忙碌时不消费。三报表新鲜度、部分/未知导出、数量、退款、地址、已发图防重放不变。

失败结果清除误导的“没有新增订单”成功说明。财务多来源的独立重试策略保持原样。

测试：test_order_login_recovery_20261022.py使用2210–2219十个固定随机种子，每轮覆盖登录等待、六种无效回执、未知导出、登录后续跑及重复触发不再发送。另跑订单补跑、报警、手动取数、登录选择及子单发送关联回归。测试不会发送真实消息。

生产证据：项目outputs/order-autopush-recovery-20261022。测试、部署、真实订单发送分别验收；登录过期必须由用户扫码，不能承诺永不失效。沿用原晚间补跑时间，不创建AI监工或额外定时。
