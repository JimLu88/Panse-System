# 定制报价 v2 — 理顺逻辑 + 提速 落地方案

> 状态：方案待拍板（本文档只设计、不改代码）。
> 数据纪律：**系数/基准价一律从我们自有表（定价表 / 配件表 / BOM）推导，绝不使用外部「扣子 v0.5」三张 Excel 的数据**；那三张表仅用于借鉴**算法逻辑**（已完成借鉴，本文已吸收）。
> 财务纪律：新管线与旧端点**并行影子运行**，不自动落任何真实订单价，灰度开关控制。

> **P0 数据体检结论（2026-06-16 实测生产库，只读）**：
> - `Material.area / width_mm / height_mm` **全表为空** → 靠板件几何的策略 A/B **不可行，弃用**。
> - 同款多档定价 **75/85 (88%) 有 ≥2 档**、63 有 ≥3 档；尺寸干净编码在 SKU 名（如「蜂蜜餐桌-1.4米」，正则 `(\d+\.?\d*)米` 可解析）→ **策略 C（多档真实价插值）定为主路**。
> - `PricingSku.wood_cost` 95% 非空 + `MW` 木材单价表干净（11 种，黑胡桃550/樱桃300/榉木240…）→ **材质 delta = wood_cost ÷ 原料单价 × (新料价−原料价) × 1.25**（反推面积，全自有数据，绕开空的 Material.area）。
> - BOM 覆盖 78/85 (92%)；`remark` 是工艺散文（夹尺寸但不结构化）→ 不作几何解析源；`WD` 前缀=「木作部分-适配X米」捆绑，印证多档尺寸锚点。

## 0. 一句话目标

把现在「5 个零散端点 + 微定制盲猜尺寸」的定制报价，理顺成**一个分类器前门 + 两条确定性管道**，并让普通定制从「2 次 AI + 近似价」降到「1 次 AI + 纯算术精确价」。

## 1. 现状盘点

### 1.1 当前 5 个端点（各自为战，无统一前门）
| 端点 | 作用 | AI | 问题 |
|---|---|---|---|
| `POST /ai-chat` | 文字+图 → 给"定制类型+方向" | 1 次 | 只建议不计算；靠解析【定制类型】行 |
| `POST /ai-quote` | 截图 → 提取+估价 | 1 次(视觉) | 尺寸调整是**盲猜**（见 1.2） |
| `POST /extract-boards` | 设计图 → 板单 | 1 次(视觉) | 每次都要 AI 拆板 |
| `POST /board-quote` | 板单 → 引擎报价 | 0 | 依赖人/AI 先给全板单，漏板=低估 |
| `POST /preview` `/confirm` | BOM 增减预览/落库 | 0 | — |

用户体验：要自己挑调哪个端点；`ai-chat` 给了方向却不出价，得再调别的。

### 1.2 微定制为什么"离谱"——根因在 `customization_ai_service._compute_price`
```
尺寸调整 = base_price × ((width_mm − nominal)/nominal) × 0.5
nominal = {小型1000, 中型1400, 大型1800}
```
- **只看宽度**、以 1400mm 拍脑袋基准、半灵敏度系数 0.5。
- 与该产品**真实板件结构无任何关系**（不知道哪些板随尺寸变、用什么料、面积多大）。
- 物料变更：名字模糊命中 `Material` → 面积×单价；命中不到就 `base×10%` 粗估。

### 1.3 好消息——参数化推算的零件已有一半
| 已有 | 位置 | 复用 |
|---|---|---|
| `compute_quote` 引擎（×1.25 工厂 / ÷0.85 畔色 / ×1.05 保守） | `custom_quote_service` | 两条管道共用 |
| **价格读取「物料表优先 + 配置兜底」** | `custom_quote_config_service.lookup_*` | 配件表=活数据源 |
| **`material_diff_surcharge`**＝(新料价−原料价)×面积×1.25 | `custom_quote_service` | **材质 delta** 直接用 |
| `quote_from_spec(db, 品类, 长, boards)` 全定制管线 | `custom_quote_service` | 特殊定制主干 |
| `PricingSku` 4 档真实价 + 成本拆分 | 定价表 | 普通定制**锚点价** |
| `Material.area / width_mm / height_mm` | 配件表 | 尺寸/材质 delta 的面积来源 |
| `BomLine.size_type`(组合/个数) + `qty_per_product` + `remark` | BOM | 哪些板随尺寸变 |

**缺口**：①前门分类器 ②每 cm 尺寸系数推导 ③品类部位模板 ④把零件组装成「普通定制增量管线」 ⑤提速（缓存/插值/合并端点）。

## 2. 目标架构：一个前门 + 两条管道

```
用户输入（文字 / 截图 / 设计图）
        │
        ▼  ① 分类器  POST /custom/classify   （仅 1 次 AI）
        │     吃「标准产品库名单 + 轻/重定义」
        │     → { type: 普通|特殊, base_product_code, confidence, 解析出的变更项 }
        │
   ┌────┴───────────────────────────┐
   │ 普通定制（改现有产品）          │ 特殊定制（全新）
   ▼                                 ▼
② POST /custom/quote-light          ③ POST /custom/quote-heavy
   纯算术，0 次额外 AI                 品类部位模板 → 引擎
   = 真实SKU锚点价                     = 自动带板单（缺料才问 AI）
     + 尺寸 delta                       + 自动推五金
     + 材质 delta                       + compute_quote
     + 增减部位 delta
```

**置信度兜底**：分类器 confidence < 阈值（如 0.7）→ 前端提示"判为 X，请确认/切换"，不擅自决定。

## 3. 数据底座（只用自有表，字段映射）

| 推算需要 | 取自 | 字段 |
|---|---|---|
| 锚点基准价（普通定制） | `PricingSku` | `daily_price`（缺则 `list_price`）；4 档可选 |

> **自建系数表的产物**：`CustomCoeff`（新表，见 §4.2）—— 每 (product_code × 轴) 一行 per-cm 系数 + 每 (product_code × 目标材种) 一行材质 delta，**由我们自有数据离线推导生成、可在后台覆写**。不引入任何外部数据。

## 4. 推算逻辑设计

### 4.1 普通定制 = 真实锚点价 + 边际 delta（anchor + marginal）
```
报价 = PricingSku 真实价(锚点)
     + 尺寸 delta（§4.2）
     + 材质 delta（§4.3）
     + 增减部位 delta（§4.4）
```
**为什么锚点 + 边际，而不是从零重算**：`PricingSku` 是已验证的真实市场价（含真实毛利/促销结构）；只把"改动的边际成本"加上去，比把整件重算更准、且天然落在合理区间。这也正是参考项目轻定制的精髓。

### 4.2 每 cm 尺寸系数（P0 实测后定稿：策略 C 为主）
求"该轴 +1cm 的售价增量"。**P0 实测：`Material` 几何字段全空 → 策略 A/B（板件几何）弃用；同款多档定价 88% 覆盖 → 策略 C 定为主路。**

- **策略 C（主路，多档真实价插值）**：同一 `product_code` 有多条不同尺寸 `PricingSku`（尺寸编码在 SKU 名，如「蜂蜜餐桌-1.4米」，正则 `(\d+\.?\d*)米`）→ 按 `daily_price` 对长度做**分段线性插值/外推**得每 cm 斜率（同时天然支持"标准尺寸免算、直接取档价"）。锚在真实价上，最稳、零板件几何依赖，覆盖 88% 产品。
  > 实测样例：蜂蜜餐桌 1.2→2821.88 / 1.4→2910 / 1.6→3041.25 / 1.8→3153.75，分段斜率平滑。
- **回退（缺多档的 ~12%）**：① 同品类多档产品聚合出"该品类平均每 cm 斜率"借用；② 实在无据 → 标「需人工核」，不硬猜。
- **轴向**：当前多档以"整体长度"为分档轴。宽/高的独立微调若客户提出且无对应档 → 走回退①或人工；**彻底废掉旧版"按宽度盲猜 ±1%/100mm"**。

> 落地：离线脚本对每个产品按 C→回退 算出每 cm 斜率，写入 `custom_coeff`；后台可人工覆写。运行时只查表，O(1)。

### 4.3 材质 delta（P0 实测后定稿：wood_cost 反推面积）
**P0 实测 `Material.area` 全空 → 不能从板件取面积。改用 `PricingSku.wood_cost`（95% 非空）反推：**
```
总木作面积 ≈ wood_cost ÷ 原材种单价(MW)
材质delta  = 总木作面积 × (目标材种价 − 原材种单价) × (1 + 工厂利润0.25)
```
`material_diff_surcharge` 已实现（×1.25），把"面积"入参换成 `wood_cost ÷ 原料价` 即可。MW 单价表干净（黑胡桃550/樱桃300/榉木240/白蜡300/红橡240…）。**全自有数据**。
> 更优先：若同类目已有"目标材种现成款"SKU（现成 `_find_sibling_by_material`），直接用其真实价差，比反推更准；无现成款才用反推公式。

### 4.4 增减部位 delta
- **追加部位**：`+ Material(部位).price × 面积/数量 ×（1+工厂利润）`（结构件再叠人工档差，沿用 `lookup_labor` 大小档）。
- **删除部位**：`− 该部位成本`（同上反向）。
- 数据来自配件表 + BOM；无新数据源。

### 4.5 特殊定制 = 品类部位模板 → 引擎 + 自动推五金
- **品类部位模板**：把现有同品类产品的 BOM **聚合**成"标准部位清单"（出现频率高的部位 + 默认材种），存 `CategoryPartTemplate`（新表）。选品类即带出整套板（不再靠人逐块录）。
  > 模板**从我们自有 BOM 聚合**生成，不抄外部表。外部表只启发"需要有模板"这件事本身。
- **自动推五金**（逻辑借鉴，阈值系统可调）：抽屉→轨道×抽数；层板→层板托×4；门→铰链×2；无把手→反弹器×开口数。
- 板单 → `quote_from_spec` → `compute_quote` 出价；只有模板覆盖不到的"真·新结构"才调 1 次 AI 补板。

## 5. 运行逻辑（分类器 + 路由）

### 5.1 分类器 prompt（doubao/本地 qwen2.5vl 均可，温度 0.3）
- 注入：标准产品库名单（`Product`/`PricingSku` 取名，缓存）、轻/重定义、强制 JSON。
- 输出：`{ customization_type, confidence, matched_product_code|null, parsed_changes:{dims, material, add_parts, remove_parts}, reasoning }`。
- 规则：命中标准库且只改尺寸/材质/色/简单增减 → 普通；"全新/特殊结构/完全定制" 或 库里无此款 → 特殊；读不到库 → 兜底特殊。
- **一次调用同时完成**：判类型 + 匹配基础产品 + 抽变更项 → 后续 0 次 AI。

### 5.2 对外只暴露 2 步
`/custom/classify` →（前端确认/可改判）→ `/custom/quote-light` 或 `/custom/quote-heavy`。

## 6. 提速方案（量化）

| 项 | 现在 | 改成 | 效果 |
|---|---|---|---|
| 普通定制 AI 次数 | ~2（ai-chat + ai-quote 视觉） | **1**（classify） | 后续纯算术，秒级、可缓存 |
| 普通定制算价 | 盲猜尺寸，近似 | 查 `CustomCoeff` O(1) + 锚点价 | 准 + 快 |
| 特殊定制 AI 次数 | 每次都 extract-boards | 模板预填，**仅缺料调 AI** | 多数 0 次 |
| 标准尺寸 | 重算 | `PricingSku` 多档**插值**直接出 | 免算 |
| 目录/模板/系数 | 每请求查 DB | **进程内缓存 + TTL**（写表时失效） | 省 DB 往返 |
| 端点 | 5 个各自调 | classify→quote 两步 | 少来回 |

## 7. Phase 0：数据体检（决定 §4.2 走 A/B/C）
落地前先跑只读体检脚本，输出：
1. `Material.area / width_mm / height_mm` 非空率（决定策略 A/B 可行性）。
2. `BomLine` 按 `product_code` 的组合行覆盖率、`remark` 是否含可解析尺寸。
3. 多档 `PricingSku`（同 `product_code` 多尺寸）的产品占比（决定策略 C 覆盖面）。
4. `Material` 木材前缀(MW)/配件(AC) 价格非空率。
> 体检只读、零写入、不碰财务。结果决定每个产品默认走哪条推导。

## 9. 迁移 / 灰度 / 财务零损伤
1. **影子并行**：新端点上线即用，但旧 `/ai-quote`、`/ai-chat` **保留**；前端加开关，默认仍走旧路，灰度切。
2. **对账**：留痕里记 新价 vs 旧价 vs（如有）人工成交价，攒一批人工核对后再放大灰度。
3. **不自动落单价**：报价只给参考，不写订单财务字段。
4. **可回退**：关开关即回旧逻辑；新表只读不影响既有。

## 10. 分阶段任务（先 Phase 0，逐阶段可独立验收）
- **P0 数据体检**（只读脚本）→ 出报告，定 §4.2 策略分布。
