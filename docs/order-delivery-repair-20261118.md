# 订单报表与送达修复

2026-11-17 的 604f2c6 将含地址、物流、商品属性但没有购买数量列的订单总表识别为发货表。真实总表使用“宝贝总数量”。新增总表内容指纹，并读取这一数量列；原误分类归档保留，同批次重新导入正确角色一次，后续仍按哈希去重。

子单的已完成部分退款与整件关闭分开：有效交易状态、金额完整、退款大于零且小于商品金额、明确完成且不涉及退货时，商品仍可生产。全退、关闭、售后、未知金额及退款处理中继续拦截。购买数量和资金事实不改，定制件数继续使用用户确认的生产数量。

每小时补推和共享目录导入后的收口均同步飞书表，即使有一张图失败，也不漏掉成功的其他订单。新增 complete_selected_order_delivery 用于明确指定的子单：图片幂等发送、同主单表格同步与回读分别报告；不会因表格失败重发成功图片。表格同步支持精确订单范围，其他订单与工厂手工字段保留。

回归包含真实表头、误分类归档重入一次、部分退款/退货/全退、确认生产一件但原购三份、表格失败重试不重复发图、限定同步与逐字段回读。两个既存支付宝扫码测试的 DummyDb 不兼容 after_collection，已在未修改的 92be03b 基线复现，未把它们当本修复通过项目。

测试、上线与实际订单送达分别验收；业务证据保存在项目 outputs/order-delivery-repair-20261118。
