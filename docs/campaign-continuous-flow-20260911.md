# 2026-09-11 用户确认的连续 Web Agent 报名流程

## 当前交付状态：程序核心已实现，真实运输绑定未完成，尚未上线

本文件及同名 JSON 记录用户本轮明确修改的长期规则，不从早期局部改价授权推导。
新流程不能调用旧的历史价格刷新、动销排除、候选扫描或预检入口。
旧的精确批次、已保存回执、固定原价和 unknown 防重放记录全部保留；不改旧 JSON
指纹让现有批次失去可验证性。新规则按版本迁移，不能把旧失败文件当新文件直接重传。

## 固定业务顺序

1. 每72小时从用户指定入口识别真实链接；AI仅承担找链接、确认新活动。入口为
   https://myseller.taobao.com/home.htm/starb/tmc-next/sale/seller/homepage.htm 。
   活动身份以店铺、活动/阶段ID、精确窗口为准，不能按标题或猜出的URL判断新旧。
2. 商品范围取 ERP 可售商品与淘宝上架商品的交集，下架不报，不按历史动销排除。
   完整产品快照须与页面商品总数核对，不能把当前页或“已选20”当全量。
3. 单品立减和超级立减分别使用各自固定官方母版的新数据副本。超级立减母版明确
   报模板错误才替换；其他活动下载本场新的SKU维度、含参考数据、不智能填价模板。
4. 同一价格版本生成两表；普通SKU报名价为ERP日常价，单品立减后按本场力度落到M/B。
   定制用既定固定基线规则，不额外叠加普通单品立减。
5. 单品立减明确成功后读回实际时间窗口，再上传活动表。已证明相同的成功立减复用。
   普通操作以页面就绪为准，目标间隔2–3秒；平台批次约180秒等终态，不把睡3秒当成功。
6. 每批错误报告只取一次，程序统一分类、修复可修复项，持续补报改变后的失败商品全SKU。
   没有任意“两轮即停”的次数限制；相同修正没有新效果不能反复提交。
7. 最后汇总成功、需轮换批准、其他无法自动处理项。轮换须用户当前确认；登录、验证码、
   无法完成的上传下载及时请求协助。完成处理不等于全部报名成功。

## 金额及分类边界

- 普通SKU相对同一ERP最终目标价的绝对差不超过2元含等号可自动修正；不能每轮再让2元。
- 我方文件报名价错了，纠正回ERP日常价；若已是日常价而平台仍要求其他标价，则人工处理。
- 明确券后/标价限制无法在目标±2元内解决时，列轮换候选，不承诺轮换清除历史或保证成功。
- 定制固定底线=既定原价×20%，不随降价重算，跨轮换继承。精确底线有分以下小数时，
  可提交最低金额向上取到分；例如541.67×20%=108.334，最低提交108.34。
- 缺基线、缺价格或分类不明都不是“必须轮换”的证据。映射必须用全量官方导出和唯一编码
  证据解决，重名或多匹配不能猜。备用SKU仍是灰色下架，保留库存。

## 已落代码及验证边界

- `scripts/campaign_continuous_policy.py`：入口/身份、新旧活动、交集、72小时、分类、固定底线。
- `scripts/campaign_continuous_flow.py`：独立持久表、同店单写入、步骤缓存、写前unknown、
  两表顺序、时间读回、成功保护、修正后的失败范围重报、重复修正收口。
- `backend/app/services/campaign_automation_service.py`：新自动入口不再执行旧预检链；
  运输未就绪时如实返回blocked，不调用旧上传或清除旧计划状态。
- `campaign_discovery_service.run_periodic_discovery`：先保存尝试时间，再执行发现；
  即使已有旧小时cron覆盖注册默认值，72小时检查点仍阻止反复扫描。未修改生产定时数据库。
- Web-Agent发现首页改为用户给出的myseller地址；新增只读能力报告，当前明确ready=false。

## 必须完成后才能称自动报名已上线

1. 用户确定上传通道：现有Edge扩展报告DOM.setFileInputFiles Not allowed；专用Web-Agent
   Edge会话需要用户同意并完成首次登录。8500按需停机本身不是故障，不改为常驻服务。
2. 将真实ERP/商品导出、固定/新官方模板及现有受控生成器接到controller的transport。
   目前测试用FakeWebAgent只做离线模拟，没有注册为真实运输，不得删除ready=false冒充接通。
3. 接入原优惠精确原位改额、终态及时间读回、原始失败报告解析、人工完成后的明确回执恢复。
   当前core对单品立减失败仍暂列人工异常，旧失败批次仍要求精确报告导入；这两项还未实现
   全量自动分类修复。已知截止/衔接时间的提前触发目前只有纯规则助手，尚未接到调度。
4. 校验真实适用SKU完整性、既有优惠及价格生成断言，由既有业务执行任务作为唯一写入者，
   实测秋季之后的超级立减（官方未开放时记录未开放，不编造未来活动或回执）。
5. 相称集成测试、正式发布、版本读回和生产72小时任务配置验收。当前未NAS部署、未平台上传。

这是一份诚实的实现检查点，不是“整个自动系统已完成”的证明。
