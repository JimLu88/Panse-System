# 飞书扫码平台选择

在提醒群 @Panse System 回复“扫码”，机器人先提供两个选项。
继续回复完整文字“店铺后台扫码”或“支付宝扫码”；不接受裸数字，避免与数量、售后等输入冲突。
“发二维码”等原有八种同义词均只展示选择，不启动浏览器。

本次入口只登录，不自动执行业务：shop → `/api/login/taobao_orders`，alipay → `/api/login/alipay_main`。
登录端点只执行既有 scan_login 人工扫码；不调用 `/tasks/*/run`，不拉订单、不导入账单。
支付宝为既有主力个人号；企业号仍使用官方API。微信、万师傅及其原有入口不变。
万师傅余额任务虽标记 platform=taobao，登录域实际为 wanshifu.com，不能按该标签归入店铺选项。

每条选择消息先持久保存意图，以 PostgreSQL advisory transaction lock 序列化认领；
共用现有扫码与编排进程锁。重复消息不重放，新消息遇到进行中或未知登录结果也不启动。
登录请求只提交一次；缺job、超时、异常保留unknown，不自动重试、不停止仍可能运行的job。
确证终态才按原轻量桥机制请求停止Agent。人工扫码/验证码门不绕过。

全部pending、订单batch/claim、成功和未知业务记录保持原样；用户完成登录后由原业务入口处理原任务。
本次发布验收使用模拟网络/登录的测试及生产源码指纹，不发送真实测试群消息，也不发起真实登录或拉单。

登录窗口在运行Web-Agent的电脑弹出，不承诺二维码发群。回复“扫码状态”只读取持久状态。
“会话已保存”不保证平台登录仍有效，原接口可能仅保存已有cookie；原业务入口须核验。
