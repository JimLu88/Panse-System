# 关系流程完整性补齐

用户要求先完成关系流程的所有功能。本次仅维护关系图、来源索引、影响审查与验证，不执行报名、订单重推、财务重算、库存修正或飞书写入。

## 验收清单

1. 保留三种视图，补全流程分支/条件与验证要求，不将横向排列当真实依赖。
2. 页面和 CLI 都能按修改文件查直接/间接影响、保护边、检查清单和未建模范围，并导出结构化结果。
3. 全量程序索引递归覆盖后端、命令入口、脚本、前端；明确部署缺源码与静态索引时效。不读取订单、配置凭据或输出源代码正文。
4. 未详细建模文件可查位置、声明和静态依赖，但不能把自动代码引用升级为已审核业务关系；未知/动态路径保留。
5. 模型字段声明、同名引用、已审核关系分层；字段错误/扫描异常不能表现为无影响。
6. 关系目录验证加强：重复对象、流程、来源、证据类别、缺失锚点、删除的锁定来源都能发现；刷新页面不得自动锁定。
7. 测试循环、边界、权限、路径安全、空目录、缺流程、坏引用、深度截断、手机页面、导出内容与零业务副作用。
8. 补足业务语义需逐域核对函数与调用，未审核项仍公开列出，不通过泛化模块标签或重锁指纹来清零。
9. 相称回归、干净提交、GitHub、群晖同版、实际页面只读验收分开记录；正式发布仍使用原发布入口。

## 十项审查结论

- 文件引用不是业务血缘；分层显示。
- 未匹配文件仍输出，不空报安全。
- 上游改动可能经多跳影响下游；有界遍历并提示截断。
- 保护边仍需要影响核查，但绝不授权自动覆盖。
- 旧节点/空目录不能让界面崩溃。
- 泳道并行/分支必须读取真实关系条件，不能从排列猜边。
- 索引不能输出文档正文、字符串常量或凭据。
- 路径只允许已索引范围，不接受任意磁盘文件读取。
- 源文件新增/删除/解析异常不被静默掩盖。
- 静态测试/上线/业务完整性分开验收，不宣称无反方风险。
