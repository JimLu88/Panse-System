# 外部开源工具选型（为各子系统挑现成轮子）

> 📝 设计稿增补（2026-06-09）。给抽象子系统①–⑦配上**具体的、调研过的开源工具**，避免从零造。
> 每条按统一骨架：**定位 / 接到哪个子系统 / 能力 / 接入方式 / 风险 / MVP / 待决策**。
> 原则不变：生产先行零风险、海外走 API、国内默认 ASSIST、能力可插拔。所有"贵/不稳/有风险"判断**原样标注，不软化**。

---

## 1. MoneyPrinterTurbo —— 接 ③生成引擎（视频赛道）

- **定位**：把"话题"自动产出**竖屏无人脸短视频**（TikTok/Shorts/视频号那种）的现成流水线。
- **接到哪**：③生成引擎 的**视频子线**（图文线不归它）；上游可吃 ②采集 的选题/素材，下游交 ④平台适配 + ⑥分发。
- **它真实在做什么**（别误解）：`话题 → LLM 写脚本 → 去 Pexels/Pixabay 搜免费空镜 → Edge-TTS 配音 → 自动字幕 → ffmpeg 拼成 9:16 成片`。
  - ⚠️ **画面是"搜来的素材库片段"，不是 AI 生成的画面**；逐条质量中等，素材与脚本相关度是最弱环。
  - ⚠️ **不是剪"你自己的素材"**（要剪自有素材用 `clipify`，另列）。
- **接入方式**：它自带 **FastAPI**（`POST /videos` 建任务 → `GET /tasks/{id}` 轮询 → `download` 取成片），**当无头微服务挂本地端口**即可，符合本系统"可插拔挂载"原则。免费路径：Ollama/免费 LLM + 免费 Pexels key + Edge-TTS + ffmpeg。Windows 原生跑。
- **风险**：MoviePy/ffmpeg/faster-whisper 偶发编码错误 → **pin 一个已知好用的 release**，别追 main；素材相关度有限，需要③的选题/关键词给得准。
- **MVP**：起一个 MoneyPrinterTurbo 服务实例 → ③对接口 POST 一个话题 → 出 1 条片 → 走 ③.5 审核工位人工过 → 手动发 1 个平台。验证"出片质量够不够用"再谈批量。
- **待决策**：⚠️ 要不要上 **MoneyPrinterPlus**（变体）——它多了 AI 图生成(SD/ComfyUI) + 国内平台(抖音/快手/小红书/视频号)**自动发**，但更重、偏 WebUI、API 集成弱，且"自动发"= 落到挂载项 D 的高风险区。

## 2. AiToEarn —— 接 ⑥分发调度 + 挂载 C(海外)/D(国内)

- **定位**：开源的**多平台内容分发 + AI 生成**工具（像开源版 Buffer/Hootsuite + AI），一键发 14 个平台（小红书/抖音/视频号/B站 + TikTok/YT/IG/X…），带排期日历。
- **接到哪**：⑥分发调度 的现成 driver 候选；它的"Publish"对应你的 C 海外 API / D 国内自动；它还有官方 **MCP server**，能直接被蜂群/本系统的 agent 调。
- **能力**：跨中西平台一键分发 + 排期；附带 Create(调 Veo/Seedance 等生成)、Engage(浏览器插件自动互动)、一个带货分佣"市场"。
- ⚠️ **关键架构风险（原样保留，不软化）**：发布/排期/OAuth/分佣**都走它家服务器**，自托管也要插它的 API key + "Relay 借官方账号"。**= 你的社媒 token 和内容要过它后台** → 隐私/依赖/封号风险，尤其撞小红书/抖音/IG 的反自动化条款。和本系统"国内默认 ASSIST、对抗能力可插拔默认关"的原则**直接冲突**——所以**只可作为 C(海外 API) 的候选**，**绝不**默认用它的国内自动发。
- ⚠️ **"赚钱"那半别当真**：它的市场是普通达人接单分佣（CPS/CPE/CPM），**无独立真实提现证据**，"被动收入"是 SEO 吹。当"分发工具"用，不当"印钞机"。
- **接入方式**：Docker 自托管(`docker compose up`→:8080)跑它的**生产/分发**那半；用能丢的小号试。它的 MCP server (`x-api-key`) 可接进 ⑥ 做"一次产出多平台投递"。
- **MVP**：自托管 → 只接 1 个**海外**平台(走它 API)→ 把 ③ 出的 1 条内容一键分发 → 看数据回收(⑦)。**国内平台先不碰它的自动发。**
- **待决策**：⚠️ 国内分发到底走 AiToEarn 还是走你自建的 D-domestic-automation(慎挂)/ASSIST？倾向：**国内永远 ASSIST/半自动**，AiToEarn 只吃海外。

## 3. Headroom（可选）—— 接 横向Ⅲ 多 LLM 路由（省 token）

- **定位**：上下文压缩层，把喂模型的工具输出/RAG/历史压 60–95% token 再进窗口（可逆）。
- **接到哪**：横向Ⅲ LLM 路由的**成本优化**侧；本系统 ②采集分析/③生成 会塞大量素材进 prompt，压缩能直接省钱。
- **接入方式**：MCP server 或 LLM 代理，零改码接。Windows 原生。
- ⚠️ **风险**：有损压缩**可能丢③事实核查需要的细节**；很新要 pin 版本。**是省钱层不是记忆层**。
- **待决策**：先在真实 trace 上验证不掉关键信息再进生产回路。

## 4. 串成一条真实流水线（本系统视角）

```
②采集/选题  →  ③生成: MoneyPrinterTurbo(视频) / 自建图文  →  ③.5 审核工位
                                                              │
                                          ④平台适配  →  ⑥分发: AiToEarn(仅海外API) / 国内ASSIST
                                                              │
                                                          ⑦数据回收 → 反哺①选题
              (横向Ⅲ: Headroom 压 token 降本)
```

- **第一步只验生产**（零风险高价值）：MoneyPrinterTurbo 出片 + ③.5 审核，**先不接任何自动分发**。符合"生产与对抗解耦、生产先行"。
- 分发**海外先行**（AiToEarn API），**国内永远 ASSIST**，与 05-deployment 的国内/海外隔离一致。

## 速查表

| 工具 | 接子系统 | 角色 | 风险 | 默认 |
|---|---|---|---|---|
| **MoneyPrinterTurbo** | ③生成(视频) | 无人脸短视频自动出片(微服务/API) | 素材搜来的非AI生成、ffmpeg偶发 | ✅ 推荐先试(只到出片) |

| **Headroom** | 横向Ⅲ LLM路由 | 压context省token | 有损可能丢细节 | 可选 |
