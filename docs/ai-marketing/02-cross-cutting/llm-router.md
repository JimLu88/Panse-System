# 横向 Ⅲ · 多 LLM 路由

> 状态：📝 设计稿

## 职责（一句话）

集中管理 LLM 调用：**哪类任务调廉价模型、哪类调顶级，按 token 成本和质量动态路由**。

---

## 核心能力

| 能力 | 说明 |
|---|---|
| **分层路由** | 任务类型 → 模型档位的映射规则 |
| **成本控制** | 按月预算 / 按账号配额 |
| **质量回退** | 廉价模型输出不达标自动升级到顶级模型 |
| **统一接口** | 屏蔽各供应商 SDK 差异 |
| **缓存** | 同 prompt 同温度复用结果 |

---

## 模型档位

| 档位 | 代表模型 | 适用任务 | 成本 |
|---|---|---|---|
| **顶级** | Claude / GPT-4o | 核心生成、逻辑重构、风格注入、hook 创作 | 1.0× |
| **廉价** | DeepSeek / GPT-4o-mini | 清洗、格式化、JSON 抽取、事实核查 | 0.1× |
| **本地**（可选） | Llama / Qwen 本地部署 | 敏感词扫描、AI 感初筛、超高频任务 | 0 边际成本 |
| **多模态** | GPT-4o vision / Claude vision | 配图分析、视觉合规检查 | 1.5× |
| **专用** | 翻译模型 / NER | 本地化、脱敏 | 0.3× |

## 关键设计决策

### 1. 任务 → 档位映射（声明式）

```yaml
routes:
  generator.logic_restructure: top
  generator.style_injection:   top
  generator.fact_check:        cheap + search
  generator.compliance_scan:   cheap
  collector.style_extract:     cheap
  collector.deanonymize:       cheap
  adapter.localization:        specialized
  review.ai_score:             local
  router.fallback:             top  # 兜底
```

**为什么**：业务代码不直接选模型，只声明任务类型。换模型时改路由表即可。

### 2. 质量回退

```
   廉价模型 → 输出
        ↓
   质量检查（JSON 结构 / 长度 / 关键字段）
        ↓
   不通过 → 自动升级到顶级模型重新调用
        ↓
   通过 → 返回 + 记录"回退发生"
```

**为什么**：成本省下 90% 但偶尔翻车时不要让业务报错。

### 3. 缓存

同一个 prompt + 同 temperature 在 24h 内返回缓存结果。
- 风格抽取：同样原文必然得到同样 DNA
- 事实核查：同样事实 24h 内不变

**为什么**：纯节省，副作用最小。

### 4. 多供应商抗风险

不绑死一家供应商：
- 一家挂了 → 自动切换备用
- 一家涨价 → 通过路由表迁移
- 一家封号 → 多 key 池兜底

---

## 输入 / 输出

**输入**：业务子系统的"任务 + prompt"
**输出**：模型响应 + 元数据（实际用了哪个模型、token 消耗、回退发生）

---

## 与其他子系统的接口

被所有需要 LLM 的子系统使用：

- ② → 风格抽取 / 脱敏
- ③ → 四层流水线全部
- ③.5 → 改写候选生成
- ④ → 平台适配 / 本地化
- ⑦ → 行动建议生成

```
┌─ 月度预算上限 ────────────────┐
│  ├─ 顶级模型：$X                │
│  ├─ 廉价模型：$Y                │
│  └─ 多模态：$Z                  │
└──────────────────────────────┘
        ↓ 超出 80% 时
   预警通知 + 自动降级（顶级 → 廉价 + 回退）
```

---

## 风险点 & 缓解

| 风险 | 缓解 |
|---|---|
| 供应商集中故障 | 多家供应商 + 自动切换 |
| 廉价模型质量不稳 | 质量回退机制 |
| 缓存命中污染（变了又被复用） | 缓存 key 包含 prompt 版本号 |
| Token 费用爆炸 | 月度预算 + 实时监控 |

---

## MVP 里做什么、不做什么

**MVP 做**：
- ✅ 路由表（YAML 配置）
- ✅ 多供应商接入（至少 2 家）
- ✅ 基础缓存
- ✅ 成本统计

**MVP 不做**：
- ❌ 质量回退（先全用同一档）
- ❌ 本地模型部署（成本太高）
- ❌ A/B 测试同任务不同模型
