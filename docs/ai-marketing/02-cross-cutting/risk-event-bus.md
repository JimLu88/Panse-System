# 横向 Ⅱ · 风控事件总线

> 状态：📝 设计稿

## 职责（一句话）

所有子系统的异常信号汇聚到一条总线，由**独立风控决策模块订阅**。

---

## 为什么独立

风控逻辑**不要散落在 20 个 if-else 里**。要解耦。

- 业务子系统只**发事件**，不做决策
- 风控决策模块**只订阅事件**，独立演进
- 上线新风控策略不需要改业务代码

---

## 事件类型

| 来源 | 事件 | 严重度 |
|---|---|---|
| ⑤ 账号 | 登录态过期 | 中 |
| ⑤ 账号 | 功能受限（禁言/限流） | 高 |
| ⑤ 账号 | 粉丝异常下跌（>10%/24h） | 高 |
| ⑥ 分发 | 发布后 3h 无互动 | 中 |
| ⑥ 分发 | API 返回限流 | 高 |
| ⑥ 分发 | 自动操作触发验证码 | 高 |
| 网络 | IP 触发风险提示 | 高 |
| ③ 生成 | 模型频繁触发某词被改 | 低 |
| ③.5 审核 | 同一模板被审核员多次拒稿 | 中 |
| 挂载项 E | 代理切换异常 | 中 |

---

## 风控决策模块输出

| 决策 | 触发条件 | 动作 |
|---|---|---|
| **暂停账号 X 小时** | 单号高严重度事件 | 写回 ⑤，⑥ 停接该号任务 |
| **通知人工** | 中严重度事件 | 推送告警 |
| **标记 prompt 模板观察** | ③.5 拒稿率超阈值 | 在 ③ 给该模板打标 |
| **触发熔断** | 多个事件聚合 | 全平台 / 全账号停 AUTO，强制 ASSIST |
| **启动养号保护模式** | 账号健康分跌出 30 分位 | 降发布频率，主推真实互动 |

## 关键设计决策

### 1. 业务 / 决策完全解耦

```
   ① ② ③ ④ ⑤ ⑥ ⑦ 挂载项
        │ │ │ │ │ │ │
        ▼ ▼ ▼ ▼ ▼ ▼ ▼
   ┌──────────────────────┐
   │   风控事件总线（Pub）   │
   └──────────┬───────────┘
              │
   ┌──────────▼───────────┐
   │  风控决策模块（独立）   │  ← 规则可在配置中心热更新
   └──────────┬───────────┘
              │
              ▼
        决策动作（写回到具体子系统）
```

### 2. 事件聚合，不要单点反应

单个事件不一定有意义，**多个事件聚合**才说明问题：

> 账号 A：3h 无互动 + 评论率突降 + 粉丝小幅下跌 → 综合判定限流，停 12h

### 3. 决策可观测、可回放

- 每个决策记录触发的事件链
- 支持回放（如果当时这样判会怎样）
- 决策错了能复盘

---

## 输入 / 输出

**输入**：所有子系统的事件
**输出**：风控决策 → 写回对应子系统 → 写日志 → 通知人工

---

## 风险点 & 缓解

| 风险 | 缓解 |
|---|---|
| 事件丢失（消息队列故障） | 双写 + 落盘日志 + 重放 |
| 决策模块本身崩溃 | 默认 fail-safe：所有 AUTO 降 ASSIST |
| 风控规则过激（误伤业务） | 决策可回放 + 灰度发布 |
| 事件爆炸（每秒 1000+） | 事件采样 + 聚合压缩 |

---

## MVP 里做什么、不做什么

**MVP 做**：
- ✅ 总线基础设施（消息队列 / Pub/Sub）
- ✅ 关键事件类型定义
- ✅ 决策模块初版（基于规则）

**MVP 不做**：
- ❌ 事件聚合的复杂模式识别
- ❌ 决策回放工具
- ❌ ML 异常检测
