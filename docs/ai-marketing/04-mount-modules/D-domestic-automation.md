## 涵盖平台

可能涉及：
- 小红书
- 抖音 / 快手
- 知乎
- 小黑盒
- 其他国内平台

每个平台一个 driver，但**每个 driver 都要承担"风控对抗"的成本**：
- 元素选择器随时失效
- 行为指纹被检测
- IP / 设备 / 账号关联被识别

---

## 关键警告（必读）

### 1. 维护成本无底洞

- 平台前端改版 → driver 失效
- 平台反爬升级 → driver 被检测
- 行为序列模式被学习 → driver 触发风控
- **每天可能都要修**

### 2. 法律 / ToS 风险

- 平台用户协议通常禁止自动化操作
- 自动化被识别 → 账号封禁
- 严重情况 → 平台诉讼 / 监管处罚

### 3. 一次失败连锁影响

- 单号被封 ← 同 IP 关联号一起封
- 同 IP 多号 ← 设备指纹相同 = 同号
- **小心你的整个矩阵被一锅端**

---

## 设计原则（如果一定要挂）

### 真实感模拟

- 操作之间随机停顿（不要稳定 1.5 秒）
- 鼠标轨迹用贝塞尔曲线，不要直线
- 偶尔"误操作"（点错按钮 → 退回）
- 行为序列随时间漂移（不要每天一模一样）

### 行为档案多样化

每个号有不同的：
- 操作速度
- 喜好元素（点不点关注、点不点收藏）
- 浏览时长分布

详见挂载项 F 配套。

### 风控总线监听

任何一次"触发验证码 / 滑块 / 异常提示"立即：
- 暂停该号自动操作 12h
- 推送告警
- 进入"养号保护"模式

---

## 维护成本评估

**高 / 无底洞**：
- 全职 1–2 人维护 driver
- 每次平台改版滞后 1–7 天
- 单个平台改 driver 通常 2–5 工作日

---

## 商业 ROI 判断点

只在以下情况启用：
- 海外 ASSIST 模式被运营员吐槽到不能忍
- 国内官方 API 完全无望
- 测试号验证 D 能比 ASSIST 至少 5x 提效，且账号存活率不降
- 你愿意接受"明天可能整批号挂"的概率

---

## 风险点

| 风险 | 严重度 |
|---|---|
| 整个矩阵号被封 | 致命 |
| Driver 失效 → 业务停摆 | 严重 |
| 法律诉讼 | 严重 |
| 维护团队疲于奔命 | 中 |

---

## 替代方案

**强烈建议先做：**
- 把 ASSIST 模式的沉浸式工作台优化到极致（单篇 30 秒）
- 用浏览器插件做"半自动"（不模拟，但减少人工步骤）
- 多人协作分摊运营负担

**这些做到极致后再考虑挂载 D**。
