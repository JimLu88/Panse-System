# 挂载项 G · 接码 / 批量注册模块

> 状态：📝 设计稿 / **默认关闭** / ⚠️ **风险最高**

## 概述

通过接码平台 + 自动注册流程批量产生新账号。

> ⚠️ **关键警告**：这是**风险最高**的挂载项。商业价值能否覆盖封号损失，需先用数据验证。

## 模块组成

```
   接码平台 API
        ↓
   一次性虚拟号码
        ↓
   挂载项 G（注册流程编排）
        ↓
   E (代理) + F (浏览器) + D (自动操作)
        ↓
   平台注册接口
        ↓
   验证码 → 接码返回 → 填写 → 完成
        ↓
   新账号写入 ⑤ 账号管理
```

---

## 风险（按严重度排序）

### 1. 法律风险

- 大量使用虚拟号码注册可能违反《网络安全法》《个人信息保护法》
- 各平台用户协议禁止批量注册
- 严重情况：平台诉讼 / 监管处罚

### 2. 账号矩阵被一锅端

- 平台识别批量注册模式 → 整批新号秒封
- 旧号被关联 → 老号一起遭殃
- IP 段被拉黑 → 该 IP 段所有号阵亡

### 3. 接码平台不可靠

- 接码服务商可能记录注册信息（隐私泄漏）
- 一次性号码可能被其他人复用 → 找回密码风险
- 服务商被打掉 → 业务停摆

### 4. 维护成本

- 注册流程随平台改动频繁失效
- 接码成功率波动（需多家备份）
- 新号"养号"周期长（不能立即用）

---

## 替代方案（强烈推荐）

不要做 G。做：

- 真实用户注册（合作 KOC / 内部员工）
- 收购老号（白市场）
- 与海外用户合作（出海账号）

这些都是"白市场"路径，长期 ROI 远高于 G。

---

## 维护成本评估

**高**：
- 每次平台更新注册流程 → 1–3 工作日修复
- 接码服务商切换 → 重写适配
- 监管变化 → 可能整体下线

---

## 商业 ROI 判断点

只在以下**全部满足**时启用：

- 真实账号获取渠道完全用尽
- 每号"养成"成本 < 商业产出 5x
- 法律团队明确通过
- 公司能承受最坏情况（整批号挂 + 监管罚款）

**任何一项不满足 → 不挂**。
