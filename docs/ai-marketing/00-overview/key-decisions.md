# 关键设计决策清单（一页纸 · 贴墙版）

> 状态：📝 设计稿

把这份当作决策备忘录贴墙上。任何架构争议，先翻这里。

---

## 11 条铁律

| # | 决策 | 为什么 |
|---|---|---|
| 1 | **事件流而非记录** | 子系统对话用事件流，所有中间产物留痕 |
| 2 | **风格输出 JSON 永不存原文** | 学结构不存表达，从源头规避版权和重复 |
| 3 | **审核工位必须量化 + 高亮 + Diff 反馈** | 单篇 30 秒是硬目标，ROI 决定性环节 |
| 4 | **prompt/模板/风格全部版本化** | 这是真壁垒，不是某个功能 |
| 5 | **driver 模式 + 统一接口** | 双模无缝降级，未来开放给三方接入 |
| 6 | **账号有性格档案** | 矩阵号同质化的根本解 |
| 7 | **沙盒预发 + 反共振调度** | 不烧主力号，不让算法抓到共振 |
| 8 | **数据回收要回标杆 + 真实感归因 + 冷启动加权** | 别被错信号误导 |
| 9 | **风控事件独立总线** | 不要散落在业务逻辑里 |
| 10 | **国内/海外物理隔离** | 战略级决策，越早分越好 |
| 11 | **挂载项默认关闭** | 对抗能力可拔可插，主架构永远干净 |

## 决策时的优先级

当不同原则冲突时，按这个顺序裁决：

1. **合规与账号安全** > 一切
2. **数据闭环可持续** > 短期效率
3. **生产侧资产积累** > 分发侧自动化
4. **可观测性** > 性能优化
5. **模块解耦** > 代码复用
