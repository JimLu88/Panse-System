# Phase 1 · MVP 阶段（1–3 月）

> 状态：📝 设计稿

## 目标

**跑通最小闭环。**

- 单平台（建议小红书）
- 5 个真实自有账号
- 全 ASSIST 模式
- 端到端验证

---

## 做的事

### 基础设施

- ✅ 建统一内容模型 + 事件流基础设施
- ✅ 多 LLM 路由（基础版）
- ✅ 配置中心（基础版，敏感词分级 + 热加载）
- ✅ 风控事件总线（基础设施 + 关键事件类型）

### 子系统

| 子系统 | MVP 要做 |
|---|---|
| ① 选题 | 多平台热榜聚合（小红书 + 1 对照）；对标博主订阅；热词衰减规则版 |
| ② 采集分析 | 接入挂载项 A（已有本地爬虫）；强制 JSON 输出 + 3 要素脱敏；基础风格 DNA 抽取 |
| ③ 生成 | 四层流水线骨架；多 LLM 路由；必改 3 节点标记；AI 感评分 + 敏感词预检 |
| ③.5 审核 | 三张体检报告（量化）；左高亮+右三改写；必改 3 节点强制勾选；Diff 留痕 |
| ④ 适配 | 小红书 + 1 对照平台；人格词典；首屏折叠线 |
| ⑤ 账号 | 账号档案基本字段；性格档案（手工）；健康心跳基础指标 |
| ⑥ 分发 | `publish()` 统一接口；assist_driver；沙盒预发；反共振调度 |
| ⑦ 数据回收 | 基础数据回收；数据看板（手动洞察）；真实感公式（手动验证） |

### 挂载项

| 挂载项 | MVP 状态 |
|---|---|
| A 本地爬虫 | ✅ 接入 |
| I 血缘追踪 | ✅ 嵌入 ②③④ |
| 其他 (B/C/D/E/F/G/H) | ❌ 不做 |

---

## 不做

- ❌ 批量注册（挂载项 G）
- ❌ 自动操作（挂载项 D）
- ❌ 代理 / 环境隔离（挂载项 E F）
- ❌ 风控对抗
- ❌ 海外平台接入

---

## 人工成本验证目标

- 单篇审核 ≤ 30 秒
- 单篇发布 ≤ 30 秒
- **1 分钟内闭环**

---

## 验收标准

- [ ] 5 个真实自有小红书账号，每个号至少 10 篇内容跑通完整流程
- [ ] 内容生成 → 审核 → 发布 端到端单篇耗时 ≤ 5 分钟（含人工）
- [ ] 单篇审核耗时 ≤ 30 秒（实测）
- [ ] 单篇发布耗时 ≤ 30 秒（实测）
- [ ] 风格 DNA 库累积至少 50 个样本
- [ ] 数据回收能产出真实感分数
- [ ] 至少 1 个真实"被复盘"案例（真实感 < 0.6 → 人工分析）

---

## 关键风险

| 风险 | 缓解 |
|---|---|
| 审核 30 秒做不到 | UI 反复迭代 + 真实审核员盲测 |
| 风格 DNA 抽取不稳定 | 多次抽取取平均 + 关键字段硬约束 |
| 本地爬虫接口不稳 | 主系统降级模式 |
| 5 个真实号怎么来 | 自有 / 朋友 / 内部员工（**不批量注册**）|

---

## 输出物（MVP 结束时）

- 一套可运行的系统
- 至少 200 篇真实发布的小红书内容
- 一份数据驱动的复盘报告（哪些选题有效、哪些风格有效）
- 30 天内不少于 5 个"已学到的教训"（反哺到 Phase 2）

---

## 下一阶段衔接

成功结束 Phase 1 后进入 [Phase 2](phase-2-expand.md)：
- 扩展到核心平台（知乎 / Ins / Pinterest）
- 挂载海外 API driver（C）
- 引入沉浸式发布工作台

如果 Phase 1 失败（30 秒目标做不到 / 数据看不到价值），先优化 Phase 1，不要扩展。
