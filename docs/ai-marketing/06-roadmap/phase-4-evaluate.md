# Phase 4 · 评估阶段（10–12 月）

> 状态：📝 设计稿

## 目标

**高阶能力按需挂载**。

到这个阶段，应该已经有充足的数据和经验来判断：

- 要不要挂 D（国内自动操作）？要的话承担多少风险？
- 要不要挂 G（批量账号）？商业价值能否覆盖封号损失？
- 要不要做 H（合规水印）作为对外卖点？

这些决策放到这个时间点，是因为**前面 9 个月跑下来，你才有数据回答"挂上去 ROI 到底是正还是负"**。

---

## 做的事

### 评估决策

每个候选挂载项过这个流程：

```
   候选挂载项
        ↓
   1. 商业 ROI 数据收集（已有数据 vs 假设）
        ↓
   2. 风险评估（合规 / 技术 / 声誉）
        ↓
   3. PoC（小规模试点 1 个月）
        ↓
   4. 数据回归分析
        ↓
   5. 决策：挂 / 不挂 / 改进后再评估
```

### 可能新增的挂载项

| 挂载项 | 评估优先级 | 评估周期 |
|---|---|---|
| F 指纹浏览器 | 中（若 Phase 3 没启用）| 2 周 |
| D 国内自动操作 | 高（风险大，慎重）| 1 个月 PoC |
| B 图片指纹变形 | 低 | 2 周 |
| H 合规水印 | 看商业化需求 | 1 个月 |
| G 批量注册 | **最低**（默认不做）| 单独立项 |

### 商业化准备

- 多租户能力
- 用户权限系统
- 模板社区开放
- 计费 / 配额

### 优化与重构

- 9 个月积累的技术债清理
- 子系统接口稳定化（准备开放 API）
- 文档完整化（准备开源 / 开放）

---

## 不一定做

Phase 4 是**条件分支**，不是固定流程：

- 如果商业化是首要目标 → 重投资多租户 + 计费
- 如果矩阵号矩阵效率是首要目标 → 重评估 D + F
- 如果合规风险已大 → 重评估 H + 监管联系

---

## 验收标准

每个候选挂载项的评估输出：

- [ ] 一份《XXX 挂载项 ROI 评估报告》
- [ ] 明确"挂 / 不挂"决策
- [ ] 若挂：上线计划 + 监控指标 + 拔出条件
- [ ] 若不挂：替代方案 + 重新评估的触发条件

整体商业化评估：

- [ ] 多租户能力上线
- [ ] 至少 1 个外部付费用户
- [ ] 公开文档 / API（如选择开放）

---

## 关键风险

| 风险 | 缓解 |
|---|---|
| 高阶挂载项决策过早 | 数据驱动，不投机 |
| 商业化拖累核心系统 | 商业化版本与核心解耦 |
| 监管变化 | 提前与法律 / 监管联系 |

---

## 输出物

- 完整的挂载项启用 / 禁用决策
- 商业化 v1.0（如适用）
- 系统稳定度报告
- 一年综合复盘
