# 连续报名局部结果接线 — 2026-09-12

本补丁不改价格/轮换/时间合同，不触发淘宝提交，也不重下固定模板。

## 固定模板范围

同一轮既有全商品导出现在保存到本轮 `product-scope.json`，分段共用同一事实。
固定母版进入生成器前，对当前商品ID/SKU ID集合做内存比对：新增、移除或换号
不再被旧母版静默吞掉。差异按商品/SKU输出，controller只隔离涉及商品，
其他商品继续，模板不重新下载。库存0不当作下架，也不把缺映射直接称为需轮换。

这只补漏项检测：全商品导出本身没有SKU上下架开关字段。同一组ID但开关变化仍需
可靠的当前启用事实；本补丁没有声称固定母版已经解决这项来源缺口，也没有自动
插入或猜测新SKU行。

## 单品立减部分成功

- 仅识别原始报告中明确的商品ID、SKU ID、失败原因列。文件哈希、同一job路径、
  物理行范围、失败数量、唯一SKU和提交范围全核对。异常dimension=A1不丢物理行。
- Web-Agent读取失败集合的补集，在实际新优惠中核对官方优惠ID、时间与每个已成功
  SKU金额。ERP独立重读报告，再核对成功补集；不能只信Web-Agent返回的布尔值。
- 整品成功的继续活动报名，整品失败的进入现有分类器。缺少可计算价格限制时按
  未识别原文处理，不凭“失败”两字授权改价或轮换。
- 同一商品内部有成功和失败SKU时保留 `partial`，原写入权威仍为unknown，禁止整品
  重传。仅该商品进最终人工核对清单，其他明确成功商品继续。局部明细及原文保留在
  终态文件中，不把“处理完成”说成“全部报名成功”。
- 无报告、未知报告布局、成功补集读回失败以及全部失败而无实际优惠ID，仍保留原始
  观察和明确阻塞。不捏造官方批号，不以测试数据代替现场失败报告。
