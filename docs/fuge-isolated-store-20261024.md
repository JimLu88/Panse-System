# 孚格独立 ERP：运行、隔离与恢复

本入口复用同一 Git 仓库，但不加载 `app.main`、畔色数据库连接、配置、调度器或业务路由。
启用范围：商品规格、独立图片上传/读取/缩略图、逐规格价格计算及证据记录、只读数据导出、离线完整备份与恢复。
未启用范围：订单、客户、库存、采购、物流、财务、通知、平台账号、后台任务、通用导入、在线恢复。调用这些接口返回拒绝/不存在，不回落畔色。

## 独立边界

- 一进程一店，启动必须明确 `ISOLATED_STORE_ID=fuge` 与绝对 `ISOLATED_STORE_ROOT`。无默认店铺。
- 专属 `store.json`、`store.sqlite`、media/thumbs/exports/backups/logs 目录。首次初始化只创建空库和独立账号，不从畔色复制任何记录或配置。
- 数据库自带 store_id + instance_id；每次连接检查。请求同时校验路径店铺、X-Store-ID、独立登录令牌。资源ID含店铺前缀，仍须查本店数据库。
- 相同哈希只在本店物理根内去重；不使用畔色图库。缩略图按请求从本店原图生成，无全局缓存。浏览器响应 no-store；登录状态仅存本店 origin 下的 sessionStorage 命名键。
- 店铺切换是不同 origin 间导航，不是在一个页面改变全局 tenant，不携带令牌/资源ID。多个标签页互不切换身份。
- Docker 只挂一个孚格目录，不挂畔色目录、Docker socket、NAS总目录或生产env；独立 internal 网络阻断外部业务访问，非root运行、只读容器根、限制内存。
- 常规导出不含密码/会话密钥；完整备份包含数据库会话但恢复立即清空。备份在私有目录，须按敏感业务文件保护。签名由独立保存的本店配置验证，跨店/篡改包拒绝，恢复只能写全新目录，不能覆盖生产。
- 操作日志只记本店动作和资源ID，不复制畔色日志。不提供自动清理/跨店恢复能力。

## 价格合同 v2

目标大促到手价 = 当前逐SKU **平台券前价 × 0.70**，不扣店铺券、个人券；不得自动拿划线原价或历史价代替。
来源须含商品/SKU、完整配置、来源URL、时区采集时间、优惠组成、适用条件和排除店铺/个人券确认。超过24小时拒绝作为当前计算输入；历史记录保留但不自动激活。
一口价、单品宝系数与官方比例显式输入，不默认0.75/0.15已经在孚格生效。普通报名价为显式日常价（标价×确认系数），官方立减按现有活动表算法，单品立减单独相减，不重复扣。
每次计算保存全部输入、版本、时间、各层金额；不会自动更新正式商品价格，更不会上传平台。目标高于活动后基价时拒绝，不用0掩盖。日常/大促无一个统一的已确认反推倍率。

## 启动（正式账号必须由用户独立设置）

1. 使用已审查提交构建 `deploy/fuge/Dockerfile`，不使用脏工作区；镜像命名 `fuge-erp-isolated:<commit>`。
2. 创建新的专属父目录（例如 `/volume1/docker/fuge-erp`），只对这个新目录给予 UID/GID 10001 写权限。不能指向畔色目录。
3. 交互初始化（不把密码写入命令、文件回执或环境变量）：
   `docker run --rm -it --mount type=bind,source=<FUGE父目录>,target=/data --entrypoint python <镜像> -m app.isolated_store initialize --root /data/store --store fuge --username <新账号>`
   程序会两次隐藏输入密码。目录已存在则拒绝，不覆盖。
4. 设置 FUGE_VERSION=精确提交、FUGE_BIND_IP=内网NAS地址、FUGE_DATA_ROOT=上述父目录后，运行 `docker compose -f deploy/fuge/compose.yml up -d --no-build`。启动前检查8290端口与发布锁，不能停止畔色服务。
5. 独立页面为 `http://<NAS>:8290/stores/fuge`。只读 `/health` 显示store和已启用/禁用模块。API不接受缺失店铺头。
6. 畔色前端构建时明确配置 `VITE_FUGE_ORIGIN=http://<NAS>:8290`，再通过现有统一发布入口发布同版API/Web。未配置时显示“孚格（未启用）”，不会跳回畔色假装已切换。孚格返回畔色链接为同主机8200端口，当前环境之外部署前须调整。

没有自动开放公网；若以后要外网访问，应先配置独立TLS入口与访问策略。不能共享畔色登录token或账号库。

## 备份与恢复

- `python -m app.isolated_store_recovery backup --root <store根> --store fuge`：一致SQLite快照及全部被引用原图，逐文件SHA256与本店HMAC。
- 单独安全备份 `store.json`，不放普通导出或公共代码库。
- `python -m app.isolated_store_recovery recover --trusted-config <本店保管的store.json> --archive <本店备份.zip> --destination <全新绝对目录>`。
- 恢复后先检查数量、原图哈希及独立身份；旧实例停用后才能挂载新目录，不能同时开启两个可写副本。原目录不改不删。

## 回滚

新环境停用仅针对精确 `fuge-erp-isolated` 项目；保留其数据目录和备份。原畔色库无需迁移或回滚。店铺入口未发布前无生产影响；入口发布后可移除VITE_FUGE_ORIGIN并按现有正式发布流程恢复上版前端。不要全局清理容器或volume。

## 验收范围与限制

测试仅用临时合成数据。负向覆盖缺/错店铺、跨店token/商品/图片、相同哈希两店物理副本、路径穿越、链接逃逸、跨店与改签备份、在线恢复关闭、并发窗口、运行中换库、禁用作业和过期/错误价格口径。
商品价格源仍由用户授权的独立资料任务提供；本程序未取得任何当前淘宝价格。没有宣称所有ERP模块已启用，也不能宣称绝对无漏洞。

## 2026-10-24 资料导入及账号设置

112款产品资料与候选图库用 catalog/catalog_media 独立保存，确认规格仍存 products；候选不自动建库存或售价。导入入口 `python -m app.isolated_store_import --handoff <已校验资料目录> --root <独立新目录>`，先验 manifest SHA，再验每张源图片，复制到本店物理目录，重复执行按源编号和图片哈希幂等。现价无证据为 null，历史价格只保留来源说明。

首次可用 initialize-locked 创建未启用账号的独立库。账户设置服务只能绑定 NAS 127.0.0.1:8292，由本机 SSH 转发访问；随机表单令牌、同源校验、一次初始化，绝不复制畔色账号。用户自行设置至少14位密码；成功后关闭设置容器及隧道。不得将设置入口开放到局域网。

畔色 Web 构建需显式设置 VITE_FUGE_ORIGIN；未配置仍显示未启用，不回落原店。正式业务部署仍走统一发布入口及原锁。孚格内部网络、独立卷、非root和只读根保持不变。


## 生产入口与大图库恢复

NAS旧版Docker对internal网络不发布宿主端口，使用无数据卷的专属nginx入口代理连接entry/isolated两个网络。fuge及setup仅在isolated网络；代理只转发两个固定上游，8290绑定局域网地址，8292仅127.0.0.1。不加入畔色网络、不挂畔色卷。主服务和入口随NAS恢复自动启动，账号设置服务不自动启动。

群晖新目录可能继承ACL。仅对新建 /volume1/docker/fuge-erp/data 设置UID/GID10001和owner读写/目录遍历权限，不能修改父级或畔色目录权限。

完整图库CLI采用backup_file/recover_file流式ZIP64，逐文件SHA验证、上限50GB、恢复到新目录、会话清空。旧的内存bytes接口仅适合512MB以内测试/小库。配置store.json需独立私密保存作为恢复信任根。原始详情单屏目录归类为详情页，保留原文件名与原字节。只导入已确认SKU，候选图不自动绑定正式SKU。
