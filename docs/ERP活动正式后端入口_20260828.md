# ERP 活动正式后端入口（2026-08-28）

## 固定边界

- ERP 商品、价格、动销排除、计划、报名行、单品立减行和预检只走 ERP 正式后端服务。
- 禁止通过浏览器逐页读取 ERP，禁止直接写数据库，禁止绕过审计和活动状态机。
- 浏览器只用于千牛等外部平台的登录态、活动发现/选择、必要上传、最终提交和官方回执。
- 本入口不会上传、提交、改价、登录、重试或外发通知。

## 正式准备入口

`POST /api/campaigns/prepare`

权限：`admin` 或 `operator`。写请求由 ERP 审计中间件记录；`workflow_key` 是跨重启的持久幂等键。同一个 key 和同一份身份数据会复用计划并重新生成最新只读结果；同一个 key 携带不同身份数据返回 HTTP 409。

01 执行端不得读取浏览器 `localStorage`、索取账号密码或保存 Bearer。生产提供一个加密落库、仅允许本端点的 `service:campaign-prepare` 身份；凭据不回显，由容器内 CLI 读取后调用同一 HTTP 端点。服务请求与 Bearer 请求经过相同的 Pydantic 校验、`workflow_key` 幂等、活动服务和 `audit_logs`，审计用户名固定为 `service:campaign-prepare`。该身份不能列计划、修改排除项、上传、报名、重试、撤回或调用其他 ERP API。

响应一次返回：

- `plan`：正式计划和活动身份；
- `grouping`：近 60 天动销分组、有效登记和无效商品号清理回执；
- `signup.rows/stats`：报名候选和整品排除证据；
- `discount.rows/stats`：同期单品立减候选和目标价证据；
- `preflight.checks/has_error`：R0-R21 全部门；
- `execution_boundary`：明确 `platform_write=false`、`account_action=false`。

## 01 无凭据调用命令

先把一次准备请求保存为 UTF-8 JSON，例如 `D:\AI\畔色ERP系统\活动准备\super88-202609.json`，然后执行：

```powershell
& 'D:\AI\畔色ERP系统\ERP程序\scripts\campaign_prepare_nas.ps1' `
  -InputFile 'D:\AI\畔色ERP系统\活动准备\super88-202609.json'
```

脚本只把请求 JSON 经 SSH stdin 送入生产 API 容器的受控入口：

```text
python -m app.cli.campaign_prepare
```

CLI 的目标固定为容器内 `http://127.0.0.1:8000/api/campaigns/prepare`，不能由调用者改路径；服务 token 只在容器进程内短暂读取，不进入命令行、stdout、请求文件、浏览器或 01 会话。退出码 `0` 表示 HTTP 2xx，退出码 `1` 表示正式端点拒绝（响应 JSON 原样输出），退出码 `2` 表示本地输入/服务身份配置错误。

### 长期超级立减更新窗口

```json
{
  "workflow_key": "campaign:super-reduce:2026-09-01",
  "name": "2026-09-01超级立减更新窗口",
  "campaign_type": "super_reduce",
  "start_at": "2026-09-01T00:00:00+08:00",
  "end_at": "2026-09-01T23:59:59+08:00",
  "qn_campaign_title": "超级立减",
  "platform_activity_mode": "long_running_update",
  "platform_active_until": "2028-07-31T23:59:59+08:00",
  "official_all_store": true,
  "official_exempt_item_ids": []
}
```

这里的 `start_at/end_at` 是 ERP 更新和核对窗口，不伪造新的短期平台活动；`platform_active_until` 是官方长期活动有效期。

### 2026 年 9 月超级 88 固定档期

```json
{
  "workflow_key": "campaign:super88:49462:49469",
  "name": "超级88现货",
  "campaign_type": "big88",
  "start_at": "2026-09-06T20:00:00+08:00",
  "end_at": "2026-09-13T23:59:59+08:00",
  "qn_campaign_title": "26年淘宝9月超级88",
  "platform_activity_mode": "fixed_window",
  "platform_campaign_id": "49462",
  "platform_united_activity_id": "49469",
  "official_all_store": true,
  "official_exempt_item_ids": []
}
```

固定大促必须提供官方标题、双 ID 和秒级档期。

`official_exempt_item_ids: []` 必须显式保留在请求中；它表示已核对官方全店立减且当前豁免名单为空，不等同于省略字段。ERP 会持久化空名单标记，使 R15 通过。对于旧版本已用同一 `workflow_key` 建立、且仅缺少这个空标记的 `draft/precheck` 计划，重新执行正式 prepare 会原位补充标记并复用原计划 ID；任何非空豁免、自由备注或其他身份字段变化仍返回 HTTP 409，不会静默改写活动身份。

## 强制规则

- 无效淘宝商品号仅允许 4 至 20 位纯数字。`5`、`待定`、`暂无` 不进入动销分组、`newly_registered` 或持久登记；迁移和服务自愈只删除这些结构无效值，不删除任何 4 至 20 位真实候选 ID。
- 已登记无动销商品不进入活动报名表，只走同窗口单品立减；恢复动销后必须显式转正。
- 真 SKU 报名价始终等于 ERP 日常价；超级立减最终价等于 ERP 中促目标，超级 88 等固定大促最终价等于 ERP 大促目标。
- 逐 SKUID 的最低标价、最低普惠券后价和占位 SKU 当前价证据缺失或过期时，R16/R17 保持硬阻塞；正式入口不会降低价格或跳过证据门。
- SKU 轮换关闭。计划中出现旧 `sku_refresh_items_authorized` 标记时 R7 直接报错。

## 整条专用链接排除

有效排除来源只有两种：

1. `campaign_item_exclusions` 中的显式商品级记录；
2. 同一淘宝商品号的全部已映射 ERP SKU 都明确为 `is_custom_placeholder=true`。

禁止依据商品名、SKU 名或“定制/差价/安装”等关键词猜测。正常家具链接即使包含占位 SKU，也不会整品排除。

- 查看：`GET /api/campaigns/item-exclusions`
- 新增或更新：`POST /api/campaigns/item-exclusions`

```json
{
  "taobao_item_id": "846844153512",
  "reason": "运营确认该商品为安装专用链接"
}
```

- 停用：`DELETE /api/campaigns/item-exclusions/{item_id}`（admin）

当前已由权威字段确认的全占位链接会自动显示；安装、作废、全屋定制等候选链接必须先核实后再写显式记录，程序不会猜。

## 01 的安全重跑条件

只有生产部署完成且以下证据均通过后，01 才能调用正式准备入口：

1. `/api/health` 和 `/api/ready` 均成功；
2. API/Web 版本一致；
3. 数据库迁移为 `0140 (head)`；
4. OpenAPI 存在 `/api/campaigns/prepare` 与 `/api/campaigns/item-exclusions`；
5. 生产规则文件版本为 `2026-08-28.1`；
6. 准备响应 `execution_boundary.platform_write=false`；
7. `preflight.has_error=false` 才表示 ERP 本地准备完成，仍不等于平台提交或官方回执。
