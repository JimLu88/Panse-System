## 1. 致命坑(踩过的, 务必照办)
1. **scp 不能用**(NAS SSH 无 SFTP)。传文件: 单文件 `ssh ... "cat > 远程路径" < 本地`;镜像 `docker save 镜像 | gzip | ssh ... "gunzip | sudo /usr/local/bin/docker load"`;图库见 §4.4。
2. **群晖内核不支持 CPU 限额** → `docker-compose.prod.yml` 已删所有 `cpus:`(只留 memory)。
3. NAS docker = `sudo /usr/local/bin/docker`;compose = `sudo /usr/local/bin/docker compose`(v2.20.1)。
4. compose 必带 `-p panse-system`(项目名) → api/web 镜像名匹配 `panse-system-api` / `panse-system-web`;`--no-build` 用载入的镜像。
5. 大传输/拉镜像会被自动转后台、输出截断 → 之后直接 `docker ps` / `compose ps` 查真实状态。
6. **PC(git-bash)无 rsync**(NAS 有 rsync 3.1.2)。图库改用户手动 SMB 复制(§4.4)。
7. **api 容器内无 `curl`**(只装 wget)→ 用 `wget -qO- http://localhost:8000/api/health`。
8. **build 别带 attestation** → `BUILDX_NO_DEFAULT_ATTESTATIONS=1` 出干净单 amd64 镜像, 否则老 docker `load` 可能加载成 `<none>`。
9. **prod compose 的 `:?` 强制变量**(JWT_SECRET/POSTGRES_PASSWORD/PUBLIC_HOST)连 build 都要能解析 → 本地 build 用占位值(运行时变量, 不进镜像)。
10. **NAS 有两个网卡 IP**: `192.168.31.21`(可用) 和 `192.168.31.199`(不通)。访问/SMB 都用 **.21**。
11. **后端版本号不能代表前端版本**：API 看 `/api/version`，Web 看 `/build-version.json`；两者完整 commit 不一致即发布失败。
12. **群晖不是源码库**：`/volume1/docker/panse` 只有 compose、数据、备份和部署产物；容器 `/app` 也没有 `.git`。禁止把“镜像里有代码”当成未 push 的理由。
