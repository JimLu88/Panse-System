## 1. 致命坑(本会话踩到, 务必照办)
1. **scp 不能用** — NAS 的 SSH 没开 SFTP 子系统(报 `subsystem request failed / Connection closed`)。传文件一律:
   - 单文件: `ssh ... "cat > /远程/路径" < 本地文件`
   - 镜像: `docker save 镜像 | gzip | ssh ... "gunzip | sudo /usr/local/bin/docker load"`
   - 图库(多文件): `rsync -e "ssh -i ~/.ssh/panse_nas -p 2222" ...`
2. **群晖内核不支持 CPU 限额**(`NanoCPUs ... CPU CFS scheduler`)→ 已从 `docker-compose.prod.yml` 删所有 `cpus:`(只留 memory, memory 限额 OK)。
3. NAS docker = `sudo /usr/local/bin/docker`(非登录 shell PATH 无它);compose 用 `sudo /usr/local/bin/docker compose`(v2.20.1)。
4. compose 必带 `-p panse-system`(项目名), 使 api 镜像名匹配 `panse-system-api`(配合 `--no-build` 用载入的镜像)。
5. 长 `compose up`(拉镜像)会被自动转后台、输出截断 → 之后直接 `docker ps` / `compose ps` 查真实状态。
