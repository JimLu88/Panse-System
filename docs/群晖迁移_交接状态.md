## 七、必须先解决的拦路问题(新会话务必注意)
1. **HTTPS/LAN 访问未定** ⚠️: `docker-compose.prod.yml` 的 web(nginx) 假设 **HTTPS+域名+letsencrypt**(443 挂 `/etc/letsencrypt`), `CORS_ORIGINS=https://${PUBLIC_HOST}`。但现在是**纯局域网、无域名、无证书、Tailscale 没装**。→ 起整套会卡在 nginx 没证书。**先跟用户定**: ① http 直接 NAS_IP 访问(改 http-only nginx + CORS 放 LAN);② 上域名+证书;③ 装 Tailscale。定之前**验证阶段只起 db+api**(用 `docker exec api curl localhost:8000/...` 验后端+迁移, 不起 nginx)。
2. **tsc 内存坑**: 512m 容器跑 `tsc` 会 OOM(exit 134), 构建要 `NODE_OPTIONS=--max-old-space-size=1536` + 不限容器内存(或用 prod 的 web-build 一次性容器, 已验证可过)。
3. **GateGuard fact-forcing 钩子**: 本仓库每次首个 Bash / 首次 Edit-Write 某文件 / 临时 .py 都要先报 4 条事实再重试。
4. **S4 切换上线不可自动**: 停 PC、切入口、终量增量 dump —— 要用户在场再做;之前先双跑比对。
