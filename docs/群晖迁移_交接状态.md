## 1. 致命坑(踩过的, 务必照办)
1. **scp 不能用** — NAS 的 SSH 没开 SFTP 子系统(报 `subsystem request failed / Connection closed`)。传文件一律:
   - 单文件: `ssh ... "cat > /远程/路径" < 本地文件`
   - 镜像: `docker save 镜像 | gzip | ssh ... "gunzip | sudo /usr/local/bin/docker load"`
   - 图库(多文件): 见 §4.4(PC 无 rsync)。
2. **群晖内核不支持 CPU 限额**(`NanoCPUs ... CPU CFS scheduler`)→ 已从 `docker-compose.prod.yml` 删所有 `cpus:`(只留 memory)。
3. NAS docker = `sudo /usr/local/bin/docker`(非登录 shell PATH 无它);compose 用 `sudo /usr/local/bin/docker compose`(v2.20.1)。
4. compose 必带 `-p panse-system`(项目名), 使 api 镜像名匹配 `panse-system-api`(配合 `--no-build` 用载入的镜像)。
5. 长 `compose up` / 大传输会被自动转后台、输出截断 → 之后直接 `docker ps` / `compose ps` 查真实状态。
6. **PC(git-bash)无 rsync** — 图库不能直接 `rsync -e ssh`(NAS 有 rsync 3.1.2, PC 没有)。方法见 §4.4。
7. **api 容器内无 `curl`**(prod Dockerfile 只装 wget)→ 健康检查用 `wget -qO- http://localhost:8000/api/health`, **别用 curl**(报 executable not found, api 其实没事)。
8. **build 出来别带 attestation** — BuildKit 默认给单平台镜像也套 manifest list + attestation, 老 docker `load` 可能加载成 `<none>`。build 时加 `BUILDX_NO_DEFAULT_ATTESTATIONS=1` 出干净单 amd64 镜像再 save。
9. **prod compose 的 `:?` 强制变量**(JWT_SECRET / POSTGRES_PASSWORD / PUBLIC_HOST)连 `build` 都要能解析 → 本地 build 用占位值(它们是运行时变量, 不进镜像);NAS `.env` 这 3 个已 set。
