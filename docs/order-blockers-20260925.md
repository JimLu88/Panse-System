# 2026-09-25 订单与流水故障修复

## 范围和证据

- 520 单精确 SKU PPS2415003051315 的图库原图明确标注 720×380×360 mm。仅添加绑定原图哈希的尺寸事实，不继承其他变体，不改变数量、成本、售价。
- 订单号中的 503 被故障分类器误判为网络状态码；尺寸待核和历史母单凭证并不能靠小时重试解决。
- 账单程序只等待 4 秒及查询后 2 秒；本次同源只读探测等待 12 秒可读到表格。因此增加有上限的就绪等待，不把空白或加载中当作无数据；不声称已证明所有历史失败均由加载延迟造成。

## 修复与验证计划

1. 保留既有子单消息、历史母单、作废凭证；不整批重推。
2. 加入精确尺寸记录；每次使用仍验证商品、SKU、图片路径和 SHA256。
3. HTTP 状态码匹配排除订单号内嵌数字；完整错误先分类，展示文本再截断。
4. 确定的尺寸/历史凭证缺口进入待核终态，停止本轮小时重试，成功标志保持 false。下一天正常新订单仍可执行，不将历史问题永久隐藏。
5. Web-Agent 等待表格下载入口、已完成历史文件或明确无数据证据；登录失效立即停止，60 次检查后仍未知则明确超时。
6. 回归网络重试、长错误、登录、延迟加载、未知状态、历史凭证不误关等用例；推送精确提交，正式发布 ERP，安全加载 Web-Agent。
7. 生产核验原图哈希与 520 单未送达状态；精确单据预演通过后只发送一次，读回飞书真实消息及子单、归档。历史 7 条未审核不得声明全量通过。

## 反例审查

- 网络错误仍须有限重试：HTTP 503/502/429 和 timeout 保持原策略。
- 程序错误和资料缺口同时出现：程序维护优先，不吞掉代码故障。
- 图片后来变更：哈希不符即拒绝使用；不同 SKU 不共享尺寸。
- 表格壳已出现但仍加载：不导出，不视为零数据。
- 登录失效：不靠延长等待绕过登录。
- 旧消息存在或送达未知：禁止补发；不以 HTTP 成功代替消息送达。

## 本地测试

ERP 定向及关键自动化回归 32 项通过；Web-Agent 就绪等待及账单回归 14 项通过。生产发布和送达结果另存运行回执，测试通过不等于生产完成。
