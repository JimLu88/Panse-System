# 交接活动程序接入与比较（2026-11-25）

正式报名继续使用原四步程序。新程序的纯核对能力已接入 ERP 原核对入口：复用已经取得的同一官方导出和当前计划目标价，活动向导显示新旧核对数量、判定、跳过原因。无需多一次淘宝导出或上传。

独立入口 `POST /api/campaigns/{plan_id}/pipeline-comparison` 接收既有 XLSX，仅 admin/operator 可用，不调用平台、不写业务库、不改计划状态。自动核对附带结果只作为本次诊断返回，不替换持久原回执；比较异常也保留原核对结果。独立比较不能证明所选文件活动身份、完整覆盖或当前平台状态。

## 哪套更好

| 项目 | 原系统 | 交接程序 |
| --- | --- | --- |
| 正式执行 | 固定四步、持久占位、未知结果保护 | 单一参数入口更简洁，但仍缺持久写入绑定 |
| 价格来源 | ERP 当前计划档位、固定基线 | 默认固定日期 JSON，规划器缺价分支可能进入定制逻辑 |
| 终态 | 原任务回执与逐SKU核对 | 上传失败/超时仍可能将总流程标为 done |
| 核对 | 识别活动中和已发布设定，独立营销记录判定 | 只检查已发布设定，定制/缺映射/缺价跳过 |
| 模板 | 原保真和范围规则 | openpyxl 重存/删除行，官方扩展属性保真尚未证明 |

结论：原系统适合继续正式报名；新程序的集中组织方式值得保留，但不能整套替换。此接入没有启用新上传、修价、轮换或重发入口，未改变业务顺序。
