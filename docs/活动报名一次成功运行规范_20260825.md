# 活动报名一次成功运行规范（2026-08-25）

本规范把 2026 年开学季报名复盘中的可复用经验固化为程序硬门。目标不是“盲目重试直到成功”，而是把所有可提前发现的问题挡在平台写入之前，只进行一次正式报名，并用平台终态与新导出证明结果。

## 唯一流程

1. 发现活动时锁定父活动、子阶段、`campaignId`、`unitedActivityId`、秒级起止时间和官方力度。任一缺失即停止。
2. 只读导出精确活动，刷新最低标价、最低普惠券后价和当前已报 SKU 证据。
3. 本地预检 ERP 在售范围、SKU 映射、价格线、占位规格、最终到手价、活动身份和发货时效。预检不得上传报名表。
4. 先建立本场候选单品立减。历史无销量名单只作提示，不得提前排除商品。
5. 报名表每行填写 `N天`，默认 `30天`，然后向目标活动正式提交一次。上传文件本身就是平台写入，不存在安全的“上传预检”。
6. 等待该批量操作进入终态，核对总商品数、成功数、失败数和失败商品清单。如果只有失败数量而没有精确商品，按双 ID 只读下载最新反馈；仍不完整就停止。
7. 仅当某商品的全部失败原因都是无销量时，才将该精确商品转为不含官方立减的单品立减兜底。不得再次提交活动报名。
8. 按标题、双 ID、秒级档期和力度重新导出已报商品，逐 SKU 核对活动价。成功证据写入结构化回执；硬失败保留安全商品现状并报警，不自动撤销、改价或扩范围。

## 完成判定

以下证据缺一不可：

- 唯一正式报名 job ID 和平台 `submitted=true`；
- 终态 `总数 = 成功 + 失败`，且范围等于本次提交的商品数；
- 失败商品清单与失败数量一致，且全部属于本次提交范围；
- 最新操作反馈原文件名、大小和 SHA-256（存在失败时）；
- 精确活动的新导出文件名、大小和 SHA-256；
- 每个成功真实 SKU 的活动价等于本次报名价；
- 无销量兜底的精确商品范围和执行结果；
- 没有第二次活动报名提交。

## 失败边界

- 登录失效、二维码、验证码、权限或平台无法访问：停在交互门，不绕过。
- 活动身份不完整、活动标题/双 ID/档期/力度不一致：上传前停止。
- SKU 缺失、错价、历史线过期、反馈属于别的活动、失败明细不完整：保留现场并停止。
- 任何撤销、暂停、移出、换链接、改价或扩大报名范围：必须有用户对精确对象的当前明确授权。
- 自动程序、页面和 AI 都不得把失败变成第二次活动报名；无销量兜底是单品立减调整，不是活动重报。

## 运行形态

Web-Agent 保持按需启动：NAS/ERP 通过主力电脑的 Wake Bridge 唤起端口 8500，任务完成后恢复空闲。不得为了活动报名把完整 Agent 改为常驻，也不得重新启用旧 Watchdog 作为替代。
