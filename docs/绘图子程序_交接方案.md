## 0. 一句话
输入"产品结构配方" → 输出**等距线框尺寸图 + 爆炸图 + DXF**。用 build123d(OCCT)真 CAD 内核,
设计师填一张表即可,任意结构/五金都能画,不再像自写 2D 那样打地鼠。

---

## 1. 背景:为什么转 A,C 教会了我们什么
- **C(自写 2D SVG 线框)** 验证了"表单驱动"方向正确,也摸清了设计师的结构要求;
  但自写 2D 遮挡有**天花板**:隐藏线会漏(右侧板冒线)、每遇新结构/五金(反弹把手、抽拉板…)都要补渲染代码并修一轮遮挡 bug。
- **A(build123d)** 用 OCCT 内核:**自动隐线消除(HLR)**、任意几何、**原生爆炸图 + DXF**。输入表单不变,但健壮、不打地鼠。
- C 的产物 `backend/app/services/wireframe_gen.py` **留作"配方 schema + 设计师需求"参考**(无调用方、惰性);A 上线后可删。

---

## 2. 范围与目标
- **输入**: 产品结构配方(见 §4)。
- **输出**:
  1. 等距线框尺寸图(PNG/SVG)——**线稿版(发工厂)** + **木色填充版(给客户)**;
  2. **爆炸图**(装配拆解,板件+五金拉开);
  3. **DXF**(给 CNC;精度取决于 BOM 是否有板件下料尺寸,没有则只示意)。
- **定制流程**: 客户报新尺寸 → 重算比例;变更的材质块**高亮 + 旁注**。
- **自带 Web UI**: 设计师按产品填配方、实时预览、存档;ERP 调接口取图。

---

## 3. 技术选型与部署
- 语言 Python。核心 **build123d**(OCCT BREP 内核)。Web: **FastAPI** + 轻量前端(简单 HTML 即可,或复用 React 栈)。
- 渲染: `project_to_viewport()` 取 visible/hidden 边 → `ExportSVG` 出矢量;SVG→PNG 用 `cairosvg`(轻)或 `wkhtmltoimage`。
- 部署: **独立 Docker 容器**,放 **D 盘 AI 新文件夹**(遵 [[feedback-d-drive-only]] D盘强制令);**不进 ERP 瘦镜像**(OCCT 几百 M)。
- **不上群晖**(R1600 + OCCT 太重);跑 PC 或独立小主机,ERP 经 URL 调它。

## 4. 配方 Schema(数据契约 — 从 C 沿用并扩展, 合成示例)
```json
{
  "product_code": "PPS26330070320",
  "category": "cabinet",                  // cabinet | table | bed | ...
  "w": 450, "d": 400, "h": 450,           // 宽×深×高 mm (外廓)
  "panel_t": 18,                          // 板厚
  "land": true,                           // 侧板落地
  "kick": 0,                              // 踢脚/底档高(前脸内收), 0=平落地
  "segments": [                           // 从下到上
    {"kind": "drawer", "h": 230, "handle": "push"},   // push反弹(无把手线)/pull/knob/none
    {"kind": "open",   "h": 166, "shelves": 1}         // 开放格 + 内含层板数
  ],
  "pullboards": [                         // 抽拉板(推拉小挡板, 较厚)
    {"at_z": 250, "thickness": 25, "depth": 380}
  ],
  "materials": {"carcass": "木", "front": "岩板", "glass_doors": false},
  "legs": null,                           // 桌/床用: {type, section, inset}
  "render": {"style": "line", "iso_deg": 30, "mirror": true}
}
```
> 设计师填的就是这张表(UI 表单)。把 §6 的词汇都做成 schema 字段。

## 5. ERP ↔ 子程序 接口契约 (本轮只设计;**确认后我再在 ERP 加, 不写代码**)
**子程序对外 HTTP:**
- `POST /api/render` — body `{recipe, format:"png|svg|dxf", custom?}` → 返回图字节/文件路径。
- `POST /api/render-by-product` — body `{product_code, dims_override?, changed_material?, custom_note?}`
  → 子程序按**存档配方 + 覆盖项**渲染(定制订单用)。
- `GET /ui` — 设计师填配方/预览/存档界面。

**配方存哪**: **子程序自己存**(按 product_code,自己的库/文件)→ 与 ERP 解耦。ERP 不存配方。

**ERP 侧要预留的接口**(用户确认后由本仓实现, 本次不动代码):
- 新建 `backend/app/services/drawing_service.py`: `render_product_drawing(product_code, **overrides) -> bytes|url`,
  读 `DRAWING_SERVICE_URL` 环境变量;**未配置 = 功能关闭、优雅降级**(与现有 `web_agent_service` 同套路, 不报错)。
- **嵌入点**:
  - 工厂下单图(`factory_sheet` / `order_sheet_archive_service`): 有图纸时把尺寸图嵌进下单图;
  - 定制订单"手动加图入口"→ 改为调本服务**自动出图**(客户尺寸→重算+材质高亮);
  - 产品页/图库: 加"生成图纸"按钮(跳子程序 UI 或直接取图)。

## 6. 家具结构词汇(子程序要支持的几何件)
- **柜体**: 侧板(落地)、顶板、底板、背板、层板/搁板、踢脚/底档。
- **开口件**: 抽屉(齐平面板)、门、开放格(凹腔可看进去)、**抽拉板(推拉小挡板, 较厚, 半抽出)**。
- **把手**: none / **push 反弹(不画把手线)** / pull 拉手 / knob 拉钮。
- **腿**: 桌/床的方腿/斜腿。
- **床**: 床架 + 床垫 + 床头板。
- **材质**: 木 / 岩板 / 玻璃(玻璃可半透或仅描边; 岩板可填色/纹理)→ 影响填色与旁注。

---

## 7. 渲染要求(C 踩坑总结 → A 直接满足)
1. 等距/轴测: **宽在右、深在左**(mirror);角度贴设计师(≈30°, 可配)。
2. **真实板厚**(建实体板件), 顶/侧/搁板都有厚度。
3. **侧板落地**(柜体到 z=0;踢脚 = 前脸内收, 侧板仍落地)——C-v2 悬空就是反例。
4. **隐藏线消除用 OCCT HLR**(`project_to_viewport` 的 hidden/visible), **绝不手写遮挡**——C 右侧板漏线就是手写遮挡的坑。
5. **尺寸**: 双箭头 + 延伸线, 数字**与线条拉开**(别压线), 水平排版。
6. **反弹抽屉不画把手线**;抽拉板要画出"较厚 + 半抽出"。
7. 两版输出: **线稿(工厂)** + **木色填充(客户)**。
