# 关系流程使用与维护

入口：顶部 **工具 → 关系流程**（`/ops-tools`，沿用原运维工具权限）。系统设置 → 运维工具入口也保留。原体检、月报和回收站在“原有工具”中，不因打开关系页而请求旧工具接口。

## 给业务同事

- **活动相关关系 / 活动程序全链路 / 飞书相关关系 / 工厂表同步流程**：顶部快捷入口。搜索同时包含业务域、流程名、字段与程序位置，飞书数量卡等跨域对象也能找到。
- 活动入口使用用户确认的 **03｜畔色活动报名**。ERP已有活动准备、映射、定价、持久执行账本、连续程序接入与对账；本机Web Agent负责固定浏览器流程。不是重新创建一个AI报名器。
- 活动关系细化为官方发现、精确窗口、商品导出、准备文件、程序接入、防重放、失败分类、定制基线、人工轮换、官方对账和飞书终态通知。原顺序“单品立减 → 超级立减 → 同窗口主题活动”不变；此页不执行这些动作。
- 飞书区分活动终态通知、订单/提醒群分流、数量询问与回复、报表口令/批次续跑、文件图片确认导入、工厂图与表、通用表绑定/字段冲突/映射、远期报备和工厂验货。群消息成功、表格写入、实际业务完成是独立结果。
- **跨程序证据边界**：本目录锁定的是当前ERP引用源码。Web Agent终态发件箱、连续执行脚本的名称和职责标在接口节点；跨程序分支保持待核标记，不把ERP接口指纹当成本机Web Agent实时版本或无人值守验收。没有读取消息正文、口令、群ID或订单数据。

- **改动影响核查**：每行输入一个项目相对路径，批量生成依赖候选、业务检查、保护事项和未建模清单；可以加入索引中的程序，再导出本次结构化检查结果。仅下载到操作者本地，不向飞书发送技术文件。
- **全程序代码索引**：包括递归后端、命令入口、报名脚本、前端声明与静态导入；未执行源码。群晖缺少的脚本/前端源文件使用同版镜像构建时的脱敏索引，明确标为发布快照，不冒充当前本机工作区。
- **流程条件明细**：泳道下方列出实际登记的流程内关系、跨流程关系、触发条件、核查要求和来源，不从步骤排列推断串行调用。

- **业务地图**：按18个域找到商品、子单、数量、制单、库存、财务、飞书等对象，点卡片查看影响。
- **流程泳道**：看参与方及阅读顺序。不是新的执行器、也不是强制把并行任务改为串行。普通有效数量无需走人工确认分支。
- **字段影响**：选字段→选展开层数→点节点看条件。实线是已核代码关系；虚线包含待核分支、缺口和禁止覆盖。所有箭头只是检查方向。
- **遗漏与过期检查**：显示源码变化、未登记文件、完整模型字段目录。也能选择任何模型字段，查找同名属性/参数/动态属性候选。候选不是类型已证明的血缘，动态SQL、JSON、反射仍可能漏检。

只读页面不访问订单记录，不发送任何群消息，不触发报名、库存变化或财务重算。角色沿用系统工具/管理接口边界，不给工厂开放内部结构权限。

## 给后续程序维护者（包括AI）

在backend目录执行：

```text
python -m app.cli.business_relationships --node quantity.physical
python -m app.cli.business_relationships --field OrderDetail.qty
python -m app.cli.business_relationships --changed backend/app/services/factory_sheet.py backend/app/services/order_cost_service.py
python -m app.cli.business_relationships --check
python -m app.cli.business_relationships --review-changes backend/app/services/factory_sheet.py scripts/campaign_prior_failure_import.py
python -m app.cli.business_relationships --source-index
python -m app.cli.business_relationships --flow order
```

每次改动的最低检查：

1. 确定权威字段与精确身份；购买量、实物量、BOM用量、锁库量、实发量、计费量不可互换。
2. 根据变更文件和字段查询影响。看直接/间接边、保护边、未登记文件与同名引用候选；不把无结果当无影响。
3. 逐项判断是否需要修改：数据来源、制单、库存、财务、飞书群、工厂表、失败收口、幂等和权限。
4. 在目录里更新实际关系、条件、来源、证据级别和检查项。未实现/未核实保持明确标签。
5. 执行相称测试及真实读回。只有审查完成才执行`python -m app.cli.business_relationships --freeze-reviewed`并提交指纹。禁止启动时自动刷新；禁止只为CI变绿而重锁。
6. `--check`和CI检查目录、锚点、指纹；只证明结构来源未变，不证明运行成功或全业务覆盖。最终回执分别记录本地、上线、外部实际业务状态。

目录单源：`business_relationship_catalog.py`；运行视图与维护CLI共用`business_relationship_service.py`。没有安装研究中提到的任何软件或图形执行引擎。

## 本次工厂投影修复的字段约定

- `原购买数量`：原交易数量；未知为空，不能擅自填1。
- `确认成品数量`：与制单事实一致；定制多计价单位须有效确认，未知为空。
- 兼容列`订购数量`继续表示生产数量，与`确认成品数量`一致；不把它悄悄改为交易数量。
- `数量确认状态/依据`：明确人工确认或普通购买数量依据；确认过期不继承。
- `生产事实状态`：数量/变体尺寸不足时明确“请勿据此新增生产”，其他制单警告另外保留。历史sent和附件保留，不自动作废或重发旧单。
- 图与表使用相同精确SKU尺寸来源。原购买量、实付、真实财务账单不变。
- 仅允许为该固定工厂表追加上述5个事实字段，不能删除/改名/改类型；冲突停止。只读预览不迁移结构。
- 部分图片待确认时，工厂表仍可同步待确认行；图片失败、表失败、同步关闭分别记录，关闭不说“已同步”。
- 数量确认后已发图回调独立记录表结果；表失败/未知不清理图片回执、不重发图。后续正常表同步会先读现有行，再增量更新，不凭超时重复创建。
