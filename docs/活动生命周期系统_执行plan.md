# 活动生命周期系统（活动报名 v2）——执行 Plan

> 2026-07-17 用户拍板。本文档为权威 spec，取代《活动联报机制_设计稿.md》与《一键改价上传_系统化改造spec.md》中与活动报名相关的部分。
> 背景：2026-07-17 88VIP 大促全店迁移实战（38 品 263 真 SKU 全部归一），本文把当天人工跑通的全部流程与平台规则固化进系统。

## 一、目标

把"活动报名 → 单品立减 → 回执核对 → 报警"整条链做成系统内一键流程，尽量全自动；
运营只做三件事：选活动类型、点选档期时间（精确到秒）、在系统提示时去千牛撤销/确认。

## 二、定价铁则（用户 2026-07-17 拍板，全店无例外）

1. **报名价（活动价）= ERP 日常价**（= 标价 × 0.75），所有产品、所有场次统一，永不再变。
2. **88VIP / 618 / 双11 / 38大促 等超大促：顾客到手 = ERP 大促价**。
3. **普通超级立减：顾客到手 = ERP 中促价**（中促 = 大促 × 1.03，系统统一系数，任务#22 落地）。
4. **无动销品：顾客到手 = 中促价 + 1 元，永久规则**（+1 防零头导致未来报名撞线）。
5. 中间的差额全部用**单品立减**一个数补齐；每场活动只变单品立减金额。
6. ERP 价格是唯一标准；不对就改千牛对齐 ERP，绝不反向改 ERP。

### 立减公式（写死进 builder，人话列名）

- 官方立减 = **向上取整到元**（平台实测：339.3→340、260.1→261）。
- 大促场（12%）：`单品立减 = 日常价 − ceil(日常价×12%) − min(大促价, 该SKU券后线)`
- 618/双11（15%）：同上，12% 换 15%。
- 超级立减场（10%）：`单品立减 = 日常价 − ceil(日常价×10%) − min(中促价, 线)`
  （10% 是否也向上取整待 7-20 实证，默认按向上取整，留配置开关）
- 无动销：`单品立减 = 日常价 − (中促价 + 1)`，占位不出行。
- `min(目标, 线)` 即**贴线**：券后线比目标低零头时让到线上（让幅告警阈值 1 元，超过则整品暂缓，不轮换、不强降）。

## 三、平台校验规则库（全部为 2026-07-17 实战实锤，编码为 preflight + 文案提示）

| R7 | **同名新建 SKU 复活老 skuId**（历史线跟回来） | 轮换白做 | 轮换核对器按 skuId 判定，不认名字 |
| R8 | 映射刷新必须同步清线（coupon_floor/enrolled_floor 挂编码、线跟 sid） | 旧线误封顶 | 刷映射事务内清线 |

| R13 | 报名价=ERP日常价；日常价−官方立减−单品立减=ERP目标价 | 任何一分偏差都可能错价 | builder 后逐 SKU 反算，偏差阻断 |
| R14 | 每场价保期限以本场说明/订单展示为准 | 固定猜7/19天会误判 | 默认19天可改；缺说明链接飞书提醒，SKU身份轮换默认关闭 |

## 四、核心流程（对应用户六点）

### 1. 动销检查与分组
- 数据源：ERP orders（platform=淘宝，近60天，剔 closed；含刷单=平台视角），按 product_code→taobao_item_id 聚合。
- 输出两组：**有动销组** / **无动销组**；无动销组即 no_sales_service 登记表（自动同步 + 手动增删保留）。

### 2. 无动销组
- (a) 名单一键导出 + 一键飞书推送给运营（促成交）；
- (b)(c) 立减批：到手 = 中促+1，档期跟当期活动窗口；卖出 1 单自动检测→提示转正（撤 nosales 立减→报名大促）。

### 3-4. 有动销组报名
- 活动类型点选按钮：`超级立减(默认中促)` / `88VIP` / `618` / `双11` / `38大促` / `其他大促`——除超级立减外全部按大促价。
- 档期开始/结束时间**手动点选精确到秒**（复用现有 Fusion RangePicker 秒级控件）。

### 5. 报名价 / 大促价对应
- 报名价=日常价、到手=大促价（见二）。

### 6. 报名后自动核对 + 报警
- 报名完成后自动触发 WA 任务下载「活动商品导出」（点`导出已报商品`→下载中心轮询新完成行→下载，复用 export_product_prices 的"顶行签名"模式）；
- **活动名称头部校验**：进入活动页后核对活动标题与 CampaignPlan.qn_campaign_title 一致，不一致立即中止+飞书报警（防推错活动）；
- 活动链接每次不同：WA 从营销/活动报名列表页按标题匹配点进（不写死 URL）；点击/下载失败→飞书报错，系统提供"手动上传导出表"入口继续核对；
- 核对维度（复刻 2026-07-17 人工核对）：
  a. J列活动普惠券后价 vs 目标到手（大促价/中促价/中促+1）——**差异 > 2 元报警**（飞书+页面红榜）；
  b. 活动价 P 列 vs 日常价；
  c. 单品立减导出（列：活动ID/活动名称/优惠级别/起止/状态/商品ID/商品名称/SKU ID/SKU名称/一口价/优惠值）vs builder 应填值；
  d. 覆盖完整性：应报 SKU 集 vs 已报集（缺失/多出都报）；
  e. 贴线让幅审计（0~1 元记录在案，>1 元报警）。

### 每日活动发现（调度）
- 每天抓单任务结束后（约 18:30，挂 backend scheduler，容错重试）：WA 抓千牛营销活动页 → 活动名称/档期/状态 → 落库 CampaignCalendar → **距开始 < 3 天的活动推飞书**提醒运营报名（去重：同活动只提醒一次/天）。
- 每天18:45扫描未来14天活动；缺本场价保说明链接时飞书提醒运营提供。确认前按19天，活动计划页面可逐场修改。

## 五、架构落点

- **模型**（alembic 新迁移）：`CampaignPlan`（name/type/tier/start_at/end_at 精确秒/qn_title/price_protection_days/price_protection_rule_url/status[draft→precheck→discount_pushed→signup_pushed→reconciled→alarmed]）、`CampaignReconReport`（per run: 汇总+逐SKU JSON）、`CampaignCalendar`（发现的活动）。
- **服务**：`campaign_service.py`（分组/builder/preflight/推送编排——复用 activity_upload_service.stage/commit 与 web_agent_service）、`campaign_price_protection_service.py`（默认19天/规则链接提醒/轮换硬禁）、`campaign_recon_service.py`（三种导出解析+比对+报警）、`campaign_discovery_service.py`（日发现+飞书）。
- **API**：`/api/campaigns` CRUD + `/precheck` `/push-discount` `/push-signup` `/recon`（自动+手动上传兜底）`/no-sales-group`。
- **前端**：改造 `ActivityAutoFillTab.tsx`（940行）：活动类型点选 → 档期秒级点选 → 动销分组视图（无动销名单+飞书按钮）→ 预检结果 →（提示用户撤销的卡点清单）→ 一键推立减 → 一键报名 → 自动核对面板（差异>2元红榜+飞书）。
- **WA 新任务**（D:\AI\Panse-Web-Agent uploader）：`export_campaign_items(campaign_title)`（标题校验+导出下载）、`discover_campaigns()`（活动列表抓取）；失败路径全部飞书报错。
- **调度**：backend `scheduler.py` 挂 `campaign_daily_discovery`（抓单后）与 `campaign_auto_recon`（报名后延时触发）。

## 七、导出文件格式（核对器解析依据，2026-07-17 实测）

1. **活动商品导出**（跳3行表头）：A商品ID/B商品名称/C营销ID/D商品状态/E SKUID/F SKU名称/G一口价/H最低标价/I最低普惠券后价要求/**J活动普惠券后价**/K建议价/L官方立减默认折扣/M建议金额/N推荐类型/O线上库存/P活动价/Q库存/R发货时间/S官方立减报名折扣/T官方立减金额。多营销ID记录并存，**只认"在活动内"状态：开场前="已发布设定"、开场后="活动中"**（2026-07-17 20:17 live 实证），逐记录分组解析；真实导出为合并单元格续行格式（商品ID/状态只在每品首 SKU 行，需前向填充）。
2. **单品立减导出**（1行表头）：活动ID/活动名称/优惠级别/活动开始时间/活动结束时间/活动状态/商品ID/商品名称/SKU ID/SKU名称/一口价/优惠值。
3. **商品批量导出**（发布模板 sheet，跳3行，需 reset_dimensions）：col0商品Id/col4一口价(商品)/col9销售属性/col11 skuId/col12价格/col15商家编码。
