# 每次报名必须完成的收尾核对

用户 2026-09-14 明确要求：不能再把历史报名记录当作全量完成；每次都检查。

## 固定位置与边界

- 正常整场、失败商品续报、精确改价授权续报三个执行分支，在输出最终结果前统一调用 `campaign_final_audit.finalize`。无跳过开关。
- 这是收尾检查，不是报名预检。原有两表顺序、日常报名价、±2元、固定首次原价20%、轮换需确认、成功/未知不重传全部不变。
- Web Agent `final_inventory` 是固定录屏只读任务。复用专用 Edge 登录，在同一真实官方地址的新只读页核对店铺、活动身份和官方时间，不操作用户原页面。
- 导出 SKU 维度、全部状态；一次生成，异步下载只认本次新批次，不点第二次导出。不填价、不保存、不发布、不撤回。
- 流程未收口或有未知写入时，保存“待核对”缺口，不触碰占用页面、不以失败为由重传。

## 每次核对的内容

1. 从本次控制器的完整商品快照取 ERP 可售与淘宝在售商品交集，逐项保留 SKU ID；核对初始范围不被缩小。
2. 普通活动按全量条数核对导出覆盖；超级立减按状态标签的营销记录总数核对，不能把撤销的历史记录数当作商品数。
3. 按具体活动、商品 ID、SKU ID 和营销记录匹配。旧撤销记录不能盖住新记录；多个有效记录保留歧义。
4. 从已冻结并校验哈希的 `time_binding.segment.price_window` 读取本场窗口，不能误用超级立减2025—2028年的长期窗口。
5. 区分已报名待生效、当前生效、已发布但生效未证实、草稿、异常、暂停、已撤销、缺少SKU报名价、无法确认。
6. 备用/下架SKU是否在售未证实，或SKU没出现在已报文件中，只列“报名范围待确认”，不直接判定漏报、失败或应当轮换。不得用库存0代替上架状态。
7. 原失败报告留作本轮处理历史；新导出是当前报名依据，两者分栏，不能拿旧失败否定同事刚完成的新报名。

## 结果与防误报

- `result.json.final_audit` 保留全量商品/SKU明细、平台状态、营销ID、来源行、导出哈希、录像、实际核对时间、目标窗口和证据缺口。
- `all_signed_up` 仅当本请求全范围SKU均有当前成功依据时成立。`all_currently_effective` 独立判断；待生效不是失败。
- 部分续报只代表本次请求，不代表全店全部完成。未知范围不得输出“全报上了”。
- Web Agent 的结果接口和最终通知再做一次同样的防误报检查。通知只截取短摘要，全量未确认项始终保存在结果文件；文件路径不得被截掉。
- 相同业务终态重复读取复用原有审计/导出，不循环下载，不重放报名。修复后的本地报告投影保留旧版本。
- `--audit-existing` 只能对已完成请求补做只读核对，禁止与任何业务恢复参数同时使用，不执行报名。
