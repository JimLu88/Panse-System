# 多子订单全链路收口

当前授权：修复工厂表漏行及旧汇总行混入，并核查财务、大盘等下游。基线8502a84。

## 已证实问题

1. 制单链已识别母单汇总，工厂表只看required标记，9旧汇总仍投影为产品。
2. 旧母单表行在同批绑定第一个子单后，后续子单仍因旧索引存在被跳过。玄关柜5127637176073040745没有表行。
3. 同步只验证已提交字段，不验证应有实体覆盖，因此漏行仍可能ok。
4. 财务成本已按真实购买行过滤汇总/服务/退款，但缺行价格时仍可能回落母SKU；未知数量默认1。母单含服务附项还可能先被归零。
5. 销售总额按母单统计本身正确；SKU销量、产品排行、月度销售占比、预聚合、需求预测部分仍读母单商品/数量。不能把整单实付和运装成本复制到每条子单。

## 实施顺序与边界

- 共用只读购买明细入口：排除母单汇总和真正服务项，保留部分退款商品，排除已关闭/全退；数量未知显式标记，不能默认为1。原交易数据不改。
- 工厂表逐子单；旧汇总原位标为历史汇总/禁止重复生产发货，保留原编号/附件/回执。唯一证明旧表行对应子单才能绑定，其他有效子单不受已确定兄弟影响。不删除人工行。
- 同步终态验证所有预期实体和字段，未唯一绑定不能ok。失败/未知不盲重放。
- 财务只修派生计算，真实账单、付款、退款、已结账数据不改。多商品缺价/未知数量标为不完整并保留原估值，不退回第一件冒充完整。可确定的派生差异需逐单前后证据。
- 报表数量来自子单，金额和总成本每母单仅一次。无法证明按SKU金额归属时独立显示“多商品订单（金额未分摊）”；数量明细不伪造零收入/零利润。不给整单运费发明分摊规则。
- 大盘实时计算读新入口；预聚合只对受影响日期重建可再生缓存，保持现金总额不变。预测仅改明细来源，不自行重写旧预测政策。
- 关系目录补齐上述边、条件和验证要求，审后更新来源指纹。
- 回归覆盖多子、旧母单、单子退款、部分退款、数量未知、缺价、费用只计一次、无重复图、重复同步、错误读回以及财务和报表总额守恒。
- 完成后push、群晖API/Web统一发布、实际表/财务/大盘独立读回。任务01仅执行既有程序的受控同步与有限派生缓存刷新，不全历史重导/重发。

## 审查结论

检查10项风险：汇总与真实子单混淆；兄弟相互阻塞；只验写入不验覆盖；数量未知填1；部分退款误删商品；母SKU掩盖缺价；金额重复；任意费用分摊；旧缓存不刷新；缺证据冒称全齐。分别以共用事实、唯一身份、完整覆盖、未知标记、退款事实、成本不完整、母单金额守恒、未分摊桶、限定缓存及独立读回验收。

无法从程序证明仓库实际已发齐；缺尺寸、缺原单价、实际数量待答复不编造。保留明确待办，不以测试数量代替现场证据。

## 实施复核补充

- 来源批量读取，避免大盘按每个订单增加一次查询。工厂表身份判定同时验证母单和原工厂号，不把已绑定的旧子单行误退成汇总行。
- 旧销售缓存实测在多个历史月份过期，增加逐日来源指纹；任何订单/子行变化使缓存失效并沿原接口返回实时查询。收口仅重建当前年缓存，不修改历史交易。
- 有精确来源、SKU、购买量及物理成本的样块，木作拆分未知不阻止已证明的物理成本修正；未知分项保留原值。不从木作未知推定为0。
- 原7月需求预测测试依赖现实日期，修成固定情景时钟；原6月木作测试仍期待已被7月14日废止的余数法，测试更新为现行配件阶梯，并增加有明确配件值的用例。没有更改对应业务政策。
- 2026-09-21 核验：2312母单、58多行组；既有严格财务计划无可写差异，但15历史记录有来源/精确SKU证据不足。该清单不是“15个漏发”；须保留为待核实，不覆盖真实账单。
