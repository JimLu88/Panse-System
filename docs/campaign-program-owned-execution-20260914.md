# 报名由程序跑完整段（2026-09-14 用户确认）

用户要求与订单导出一致：AI只负责开头确认和最后汇总，不实时跟进中间任务。

## 唯一业务入口

1. 每3天的既有任务从固定官方入口的程序快照确认真实活动、店铺、ID、精确窗口和是否新活动；不猜地址、不新增预检。
2. 确认冻结规则及可售∩上架范围后，调用 Web-Agent `POST /api/campaign/continuous/start` 一次，保存 request_id。程序执行完整导出/生成/单品立减/时间读回/报名/下载错误报告/分类/获准修正/改变后的失败范围重报。
3. `running` 只表示已接单，不是报名成功；AI不逐job轮询、不按步骤重新dispatch、不因三分钟等待超时重传、不反复唤醒02/03。中间状态由持久控制器及固定Web-Agent处理。
4. 原任务有已验证终态但控制器读回中断时，由程序根据原job身份与原回执接续；只读等待一次，不重放已消费写入、不释放claim。未知、登录验证、证据不一致或不支持的故障保持真实例外。
5. 结束时程序把结果与通知事件原子写入本地数据库。`GET /api/campaign/continuous/outcomes` 提供最终结果；飞书提醒群接收终态通知，不改发微信或订单群。普通通知23–08点静默、每日最多一条；真实阻挡即时通知。每个事件仅一次发送尝试，送达未知不盲目重发。
6. AI在终态或真实例外出现后统一说明平台成功、动销不足、需人工确认/轮换及未知；程序缺陷一次交02，修复后只按证据接续原请求。不要恢复10分钟AI监工。
