# 计划 8 六条草稿原位恢复 V3

## 目标与边界

V3 只处理 `campaign:super88:49462:49469` / plan 8，固定淘宝活动
`49462/49469/3527841611`、阶段“超级88现货”、12% 力度和
`2026-09-06 20:00:00` 至 `2026-09-13 23:59:59`。它不再使用候选商品页判断
已有草稿是否可报名。

程序只允许按以下顺序执行一次：

1. 从官方页面/导出只读锁定 6 条草稿、3 条已发布保护记录、旧 53 条单品立减，
   并从官方候选接口读取新增 8 个真实 SKU 的当前价、最低标价和合格活动价上限；
2. 为 Web-Agent 当前租约生成 reservation token，ERP 确认全部基线后才创建父 attempt；
3. 只补固定 8 条单品立减；
4. 只给 `1036279566778`、`1074244132390` 两条草稿各补 4 个固定 SKU；
5. 发布固定 6 条草稿；
6. 再次官方只读导出，逐商品、逐 SKU 和逐价格确认 6 商品、78 SKU、18 定制 SKU，
   并确认旧 53 条立减及 3 条保护记录完全未变。

商品 `793202812082` 和仓库商品 `1038725569412` 不进入任何写入范围。V2 已永久
退役；任何已 claim、失败或未知终态只能走 V3 的 `readback` 只读判定，不能再次提交。

## 一次性与忙碌语义

Web-Agent 的 `inspect` 返回 reservation token，并在同一淘宝 profile 租约下保留到
`commit`。订单任务占用时返回 `taobao_profile_busy/pre_write_busy`；ERP 此时不创建
`CampaignExecutionAttempt`，因此不会消耗写入机会。ERP 创建的父 attempt 是唯一业务
写 claim；V3 不调用通用 `push_signup`，不会再生成内层 signup attempt。

reservation token 原文只用于紧接着的 commit，不写数据库、不打印；attempt 只保存其
SHA-256。ERP 将 attempt 的 `write_claimed`、计划状态 CAS 和全部基线一次事务提交，
不留下已建 attempt 但未 claim 的缝隙。Web-Agent 在消耗租约前必须携自身服务令牌调用
ERP 固定只读 claim-verification 接口，确认 attempt、双 scope 与 reservation token hash
都完全一致。commit 一旦开始，无论成功、失败还是结果未知都不允许自动重试。

## 固定入口

正式执行一次：

```powershell
powershell -ExecutionPolicy Bypass -File "D:\AI\畔色ERP系统\ERP程序\scripts\campaign_recover_plan8_final_v3_nas.ps1" -ExecuteOnce
```

只有执行结果明确给出已生成 attempt、但最终核验未闭环时，才允许只读恢复判定：

```powershell
powershell -ExecutionPolicy Bypass -File "D:\AI\畔色ERP系统\ERP程序\scripts\campaign_recover_plan8_final_v3_nas.ps1" -ReadbackOnly
```

维护任务不得执行上述命令。HTTP 入口只接受 service:campaign-prepare 身份和固定请求，
无 `-ExecuteOnce` / `-ReadbackOnly` 或同时提供两者都会拒绝。响应体在非 2xx 时仍原样
输出，便于判断是写前可恢复忙碌还是已 claim 后禁止重试。

## ERP 与 Web-Agent 契约

ERP 调用固定 `POST /api/campaign/plan8-final-recovery-v3`。请求包含
`phase=inspect|commit|readback`、固定 manifest 和哈希。inspect 还必须返回官方 artifact
哈希、6 草稿 before hash、3 保护记录 before hash、旧 53 条完整 canonical 行与 hash、
新增 8 SKU 的完整候选价格证据、全记录 ID、排除项和 reservation token。新增 SKU 必须
满足当前价等于 ERP 报名价、报名价不高于最低标价和平台合格建议活动价上限，证据过期、
缺行或曾勾选商品都会在 ERP claim 前停止。commit 必须回传 written 与 already-correct
两集合的精确并集、2 条补 SKU record ID、6 条发布 record ID 和全部 checkpoint；readback
必须回传相同基线、逐 SKU 报名价和最终官方 artifact 哈希。

Web-Agent 在 commit 前只读回查：
`POST /api/campaigns/recover-super88-plan8-final-v3/claim-verification`。请求只含
`attempt_id/workflow_key/plan_id/operation/scope_sha256/inspect_scope_sha256/`
`reservation_token_sha256`，只接受 `web_agent_token`；响应不包含凭据或 manifest。

任意活动身份、记录 ID、SKU 数、SKU ID、报名价、立减值、状态、基线 hash 或额外记录
漂移都必须失败即停。
