范围：2026-09-10用户授权修复独立审核发现的问题；不改活动规则和6小时同步频次。

- 飞书全表读取要求明确has_more、有效next token、无重复token/记录ID；最多1000页。异常抛错，不将部分记录当全量，不据不完整表写入。分页异常固定回归与随机订单验收分开计数。
- 0154仅增加orders.platform_field_state可空JSON，既有订单不填元数据、不清历史备注/物流。原人工remark、发货月份和工厂身份不变。
- 买家留言、商家备注、运单分别记录列是否存在、所有行/别名值是否一致、来源sha256、抓取文件观察时间、上次值哈希与清空意图。缺列、短行、混合空/非空、冲突值、子单覆盖不完整都不作为整单清空。
- 可信自动入口沿用agent_ingest_service._import_one及口令恢复，读取既有agent输出目录的文件mtime；相同文件hash已有归档时取mtime和首次归档时间较早者。不是把解析时间或用户上传时间当平台导出时间；未验证的时间不赋予清空权。只有受控目录内文件能提供此来源。
- 来源时间只表示保留下载文件的观察时间，不冒充淘宝服务器账单生成时间。48小时限制仅用于破坏性清空；非空导入不因文件年龄冻结。已知版本必须单调向前，同hash/旧版本不重放；手工值与上次已知值不匹配或字段人工档案锁定时保留。
- 缺时间的既有非空导入保留兼容行为，但不继承旧快照清空权限；在新的可信一致快照建立来源之前，不可清空该值。人工主备注及独立人工月份不在此写入范围。
- 运单清空还必须具备上次可信已发货/签收→本次可信待发货的状态反转；原发货日期仅在与已记录日期一致时随撤销清空。非空运单的原人工保护保留，不从未知空串推断撤销。
- 飞书端清空再次比较原值哈希：已是空则幂等，仍等于原系统值才清；与来源原值不同视为人工冲突，保留并报明确失败，不谎称完成。多子单未分配物流仍不写入。
- preview/sync结果新增clear_intents，包含来源时间/hash和目标原值匹配情况；CLI对订单身份哈希化。`python -m app.cli.factory_dispatch_audit --source-status`只读输出最近25份淘宝归档状态及来源元数据数量，不触发新抓取/导入。归档时间不等于抓取成功，unknown不填造成功。
