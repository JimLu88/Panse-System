# 每次推送后的原始报表核对

2026-11-18 用户固定要求：全部推送完成后，将飞书订单与导出的订单报表核对；有缺失就补推飞书表格和工厂订单图，补后再次核实。

## 执行范围

在既有定时推送、补跑、发货口令恢复、手动推送、独立报表恢复和数量确认后调用 `order_post_push_audit`。不新增定时任务。日报须等待核对结果，未通过时发送具体缺项，不能发送“全部完成”。

按原始三报表归档清单、角色、批次和SHA256校验来源，从订单总表与销售明细重新读取母单和真实子单。以子单身份检查ERP、原购买数量和商品编码；工厂图及飞书订购数量使用已确认成品数，不能把定制计价份数当件数。来源缺行、未知状态及无具体编码分别列为异常，不静默忽略。

完整批次使用原收口记录，业务日仅接受今日或昨日；独立恢复可传原三文件ID，仍校验同日、角色、hash及已导入状态。不得把旧批次核对成功套到新失败attempt。

## 自动补缺

1. 确证ERP缺失且原行唯一时补回；已有商品或数量冲突不覆盖。
2. 正式图确证未发时走既有原子发送保护；地址、定制成品数量等门继续生效。未知发送结果不重发，已发送旧图缺内容证据也不擅自重发。
3. 飞书缺行/附件走既有字段归属与图片签名同步，只写系统管理字段。缺行不重复发送工厂群图片。
4. 补后直接读取飞书，核对订单号、子订单号、SKU、成品数量、工厂下单号、图片附件和已发图内容快照。仅接口返回成功不算通过。

一轮有界补缺，每次最多500条发送，未完成项保持失败；无无限重试。每次写入唯一 `order_post_push_audit:<uuid>` 记录，保留原始证据、排除原因、补缺数、已核实项和剩余项。只读模式不补发、不改库、不写回执。

## 验证

测试覆盖真实形状原始XLSX、缺ERP、缺飞书行、缺图、重复调用、被篡改来源、未知发送、定制数量、表格假成功、缺全单明细和先核对后通知。正式发布及现场结果以项目 `outputs/order-post-push-audit-20261118` 为准。
