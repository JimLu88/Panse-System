# 飞书确认实际成品数量

用户2026-09-20要求：系统不知道实际数量时先发待确认通知，在飞书回复1/2确认实际成品数量，再发正式制单图及解释文案。不得先给工厂一张含未确认数量的生产图。

## 实现

- 沿用现有订单逐子单发送、飞书长连接/回调入口，不需要AI盯群。原 production_quantity_unverified 分支创建一次待确认卡片，其他子单继续。
- 卡片仅有原工厂号、主子单号、产品、规格、购买量、备注及操作指引，不含客户地址；注明请勿生产。回复本卡片并@机器人填写正整数，支持件/张/套单位。
- 只认持久化卡片对应消息线程、原ERP目标群、人类回复；通过官方GET回读消息实际内容/发送人/父消息/群/删除状态，不能用任意回调中的数字直接写确认。不扩大通讯录/群历史权限。
- 订单行锁+持久化确认绑定子单、SKU、购买量及备注指纹；首次有效回复后只续推这一条，原购买量与财务不变。重复回复不重发；不同数量不覆盖，明确提示人工核对；已取消、退款、变化、sent/unknown不放行。
- 原有图片送达防重仍由子单持久声明管理。确认卡与解释发送在外发前存claim，未知结果不重发；生成正式图后回帖说明购买量、实物量、确认人，并更新原卡片。解释失败不反转图片sent。图已送而解释尚未开始时由下一次既有订单程序恢复解释，不重发图片、不新建定时。
- 普通数字、其他群/卡片、机器人回复不会被当作确认。信息不足继续待办；不解除规格尺寸或其他保护。
- 原购买数量为空/无效时不采用1件显示兜底：未确认前进入同一数量卡片流程，原购买量显示“未知”，不能用显示默认值发生产图；人工确认后仍保留原始数据，不回填伪造购买量。

## 两轮审核

1. 业务审核：待确认卡不作为生产单；只有实际负责订单的人回复才作为事实；主单与子单分离；1/2不是按金额推导；旧514/515成功及其他订单不重推。
2. 安全/故障审核：真实消息回读，精确父线程，串行锁及持久claim；变更失效、取消/退款、重复/冲突、发送超时和中断均有边界；通知失败不把已发图变成未发。
