# 企业微信接收发货密码

## 目标与边界

ERP 通过企业微信自建应用接收文本命令 `发货密码：实际密码`（也兼容空格分隔），完成签名与成员校验后，复用现有订单恢复链：保存最新密码、重试解密发货报表、导入地址、收口三报表并续推未送达的下单图。

企业微信群机器人 Webhook 只用于 ERP 向群内发送结果通知，不能接收群消息；入站密码使用独立的自建应用消息回调。

## 安全规则

- 回调只接受企业微信协议的 SHA1 签名和 AES-256-CBC 加密消息。
- 解密后的企业 ID 必须与配置的 CorpID 一致。
- 发送人必须在 `allowed_users` 成员 UserID 白名单中；空白名单默认拒绝全部。
- 只接受明确带 `发货密码` 前缀且有分隔符的文本，不识别裸密码或泛化的“密码”消息。
- 企业微信消息 ID 持久化去重，平台重试不会重复执行订单恢复。
- Token、EncodingAESKey 和以后收到的发货密码均加密落库，不在 API 响应、日志或通知中回显。
- 回调快速返回 `success`，耗时的解密、入库与续推在后台执行。

## 一次性启用

1. 在企业微信管理后台创建或选择 ERP 自建应用，开启接收消息。
2. 准备企业 ID（CorpID）、回调 Token、43 位 EncodingAESKey，以及允许发送密码的成员 UserID。
3. 给 ERP 提供一个公网可访问的 HTTPS 地址，并把 `/api/wechat/callback` 路由到当前 ERP Web/API。现有 LAN 地址不能直接作为企业微信回调地址。
4. 在 ERP“管理员控制台 → 系统监控 / 看门狗 → 企业微信接收发货密码”填写配置并启用。
5. 在企业微信后台保存回调地址；平台 GET 验证通过才算接收入口生效。

没有明确批准时，不开放 NAS 公网端口、不改路由器/防火墙，也不代替用户登录企业微信管理后台。

## 验收口径

程序部署成功不等于微信接收已启用。完整生效需要分别满足：

1. GitHub `origin/main` 包含实现提交；
2. NAS API/Web 同一提交且健康；
3. 生产 OpenAPI 存在 `/api/wechat/callback`；
4. 管理后台配置显示“已启用”；
5. 企业微信后台 URL 验证通过；
6. 用一条非生产测试口令验证签名、白名单、去重和接收回执（不得触发真实订单补跑）。
