# 企业微信接收发货密码

## 目标与边界

ERP 通过企业微信智能机器人在群聊接收发货密码；原自建应用单聊入口继续兼容。完成签名与成员校验后，复用现有订单恢复链：保存最新密码、重试解密发货报表、导入地址、收口三报表并续推未送达的下单图。

企业微信群 Webhook 机器人只用于 ERP 向群内发送结果通知，不能接收群消息。群聊入站必须使用企业微信“智能机器人”的 API 回调；它在“安全与管理 → 管理工具”中创建，不是应用列表里的自建应用。

## 安全规则

- 回调只接受企业微信协议的 SHA1 签名和 AES-256-CBC 加密消息。
- 自建应用解密后的企业 ID 必须与配置的 CorpID 一致；企业内部智能机器人按协议使用空 ReceiveId。
- 发送人必须在 `allowed_users` 成员 UserID 白名单中；空白名单默认拒绝全部。
- 支持 `发货密码xxx`、`发货密码 xxx`、`发货密码：xxx`、`密码xxx`、`密码：xxx`、`发货口令=xxx`、`口令 xxx` 等写法。
- 裸密码只在已验签、已解密、发送人已进入白名单且群消息已 `@` 精确机器人名称后启用；自建应用单聊仍拒绝裸密码。
- 企业微信消息 ID 持久化去重，平台重试不会重复执行订单恢复。
- Token、EncodingAESKey 和以后收到的发货密码均加密落库，不在 API 响应、日志或通知中回显。
- 回调快速返回；智能机器人使用平台提供的一次性 `response_url` 在原群确认“已接收”，耗时的解密、入库与续推在后台执行。

## 一次性启用

1. 在企业微信管理后台进入“安全与管理 → 管理工具 → 智能机器人”，创建内部智能机器人并选择 API 回调模式。
2. 记录机器人名称、回调 Token、43 位 EncodingAESKey，以及允许发送密码的成员 UserID。
3. 在 ERP“管理员控制台 → 系统监控 / 看门狗 → 企业微信接收发货密码”的“群聊智能机器人”区填写并保存；完整回调地址使用公网 HTTPS 域名加 `/api/wechat/aibot/callback`。
4. 回到企业微信后台保存回调地址，平台 GET 验证通过才算接收入口生效。
5. 把新智能机器人加入目标群；群内 `@机器人` 后发送任一支持格式。

旧自建应用单聊入口仍为 `/api/wechat/callback`，需要 CorpID、独立 Token/AESKey；两套回调凭据不能混用。

没有明确批准时，不开放 NAS 公网端口、不改路由器/防火墙，也不代替用户登录企业微信管理后台。

## 验收口径

程序部署成功不等于微信接收已启用。完整生效需要分别满足：

1. GitHub `origin/main` 包含实现提交；
2. NAS API/Web 同一提交且健康；
3. 生产 OpenAPI 同时存在 `/api/wechat/callback` 和 `/api/wechat/aibot/callback`；
4. 管理后台群聊配置显示“已启用”；
5. 企业微信智能机器人后台 URL 验证通过，并已加入目标群；
6. 用一条非生产测试口令验证签名、白名单、去重和群内接收回执（不得触发真实订单补跑）。
