# 超级立减异常恢复试验与单品立减修正分流

## 本次修复计划与边界

用户经03明确要求把本次步骤固化，避免乱试。分四步实现：

1. 显式区分 `single_discount_amount_fix`（单品立减金额修正）与
   `super_reduce_abnormal_recovery`（超级立减价格达标、状态异常的恢复试验）。
2. 后者只接受本次精确授权、固定官方活动模板、官方当前导出和整商品完整SKU；
   原活动价、10%比例不变，只生成文件或登记03已生成的同一文件。
3. 持久登记试验身份与文件。原106单品立减不重传；用户明确授权的异常活动试验
   是另一个业务对象，不能因为单品成功就禁止。活动中、未知在途、未授权商品仍保护。
4. 回归任务混用、错模板、部分SKU、金额/比例变化、伪空dimension、合并单元格、
   重复执行及终态误判。安装本机脚本并交03，不改NAS、Web-Agent、ERP价格或订单。

## 固定入口

`python scripts/campaign_cap_batch.py recovery-trial prepare --request request.json --output-dir <新目录>`

已有03交付文件时，使用同一入口的 `adopt --request request.json --workbook <原文件>`，
它逐ZIP部件比对重新计算的正确文件，不另生成第二份上传表。

03已经生成的固定交付回执可直接使用 `adopt-delivery --receipt <交付回执.json>`，
自动规范化既有精确授权与事实来源。单商品回执保留item/原营销ID；本轮新增全量授权
按marketing_records（商品ID→原营销ID）及完整scope处理一次性14件批次，不循环逐件制表。
占位时检查与其他批次的商品交集，不能通过改文件名、合并批次来重放已交付样块。

本轮两份原上传表后来在原目录缺失，03核查项目outputs与桌面未找到；原因未知，
不声称被删除。原交付回执与官方结果仍在。使用同入口的
`register-result --receipt <原交付JSON> --result <官方结果xlsx> --result-sha256 <官方原件hash> --operation-reference <明确原操作引用>`
只登记历史结果：检查原授权、原价完整SKU、原营销来源及官方Z/AA范围/价格/比例，
保留原回执中上传表hash但明确`original_workbook_verified=false`、`original_workbook_missing=true`。
不计算或重建上传表，和prepare/adopt共用商品范围防重传占位。之后允许同操作只读状态读回，
原文件缺失不会阻断结果登记；若后来出现文件且hash不一致仍阻断。操作引用由03对照用户
上传批次提供，不能声称是从官方XLSX提取的服务端导入任务ID。

请求schema为 `campaign_recovery_trial_request_v1`，明确experiment_type、campaign、
item、original_marketing_id、official_rate=`10%`、scope全部SKU及原价；
authorization/source/master均带path和sha256。授权材料须说明精确商品、原营销ID、
全部SKU、原价/比例不变及当前用户指示。程序验证结构、来源hash及范围一致；
不能以本地JSON自身证明用户确实授权，操作者仍对原用户消息的真实性负责。

单品立减类型返回对应已有处理入口，绝不输出超级立减试验文件；旧prepare仍停用。
本次固定母版含样块全部SKU，直接调用 `fill_selected_rows` 即可。旧参考价/状态
不作为现况，最终价和全SKU范围来自当前官方导出；母版缺SKU或历史成功状态冲突时
明确停止，不能擅自改母版、拿示例SKU补齐或重写保护来凑表。

## 持久日志与真实验收

默认账本位于 `活动准备/报名状态/recovery-trials`（本地JSON，不是ERP业务库）。
按活动+对象+商品独立占位，不随请求文件名/输出路径变化放行第二份；生成中断保留未知，
prepared也不能当平台提交。账本不阻止人直接去平台重复上传，用户仍只上传一次。

`record --trial-dir <入口返回的账本目录> --event event.json` 仅消费已取得的证据文件。
`risk_warning`、`export_refresh`、`user_uploaded`不是成功；官方终态须类型正确、原试验
文件hash、精确商品/活动和操作引用一致。成功还必须消费同一营销记录的完整官方导出，
全部SKU活动中、价格/比例不变且券后价满足，无重复当前记录，才为`recovered_this_trial`。
终态failed/unknown都保留、不重试；允许只补录同一官方操作的回读，不触发再提交。
不因单个试验成功自动扩到其他商品，`automatic_expand=false`永远保持。

脚本解析官方结果列并校验精确范围及证据hash，不能替代03核实截图和上传批次对应；
缺官方原文或同营销读回不标恢复。无外部调用、无上传、无撤回、无改价/轮换、无服务重启。
