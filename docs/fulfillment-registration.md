# 物流发货登记与紧急订单

订单看板的“紧急订单”显示内部目标、原交期及原因。每天北京时间 09:10 将当前待跟进单合并到 ERP 通知中心。近期交期沿用 11 天；不修改平台或订单原截止日期。备注需有明确起算依据，送达承诺需要核对运输时间。渠道清单讨论期间不向飞书群广播这份汇总。

同事在登记群 @Panse System，发一条图文，附工厂下单原图，正文为 `发货登记 整单单包已发 物流公司 运单号`。物流公司填写淘宝承运商完整名称；该指令代表同事已确认整单单包实际交运。正常回执回复原消息。“订单看板 → 发货登记”可查最近 200 条和待核原因。转发压缩图可用 OCR 提取工厂号与子单号供核对，不能据此自动放行。TOP 未启用时，精确原图核对通过后进入“待出表”，不触发淘宝提交。

## 官方批量表（2026-11-18）

在订单看板的“发货登记”点击“新增发货登记”，填主交易单号、完整物流公司和运单号。程序展示该主单全部导入子单、规格、数量和备注；员工确认全部商品由同一运单实际交运，且拍照等备注已落实后登记。多件、多子单只允许这样人工确认整单；部分发货、多运单、退款、未付款、已发货、延期或等通知不能进入批量表。中通快运与中通快递需分别填写，不用模糊简称。

勾选“待出表”记录，点击“生成官方批量表”。母版来自用户提供的 `批量自己联系发货.xlsx`，保存在 `backend/app/assets/taobao-bulk-self-shipping.xlsx`，SHA256 `fb86b967f57f4033beedfc6092cc26b829f03d1ecf8bc7cb688f694b6dca2faa`。仅填主交易单号、快递公司名称/编码、运单号三列；订单与运单全部文本保存，模板其他ZIP部件原字节保留。每批应用限额200单，不代表淘宝上限；不同店铺不混批。

生成前重新核对订单快照；主单和运单持久占位，另一批不能重复出表。断网沿原请求恢复；下载原批次取得相同文件。出表不改订单、库存和财务，也不代表平台接受。后台自动上传及官方结果回读尚未接通：当前需同事从淘宝“自己联系物流 → 批量导入”上传，并核对导入/导出记录；结果不明不能再次导入。打开入口不要求程序随机选取某一订单发货。未提供虚构成功或自动释放占位按钮。

本轮浏览器工具对淘宝登录域返回站点安全拒绝，不能换 Edge/CDP/脚本绕过。已有 Edge 登录不等于自动上传验收。此版本交付登记、核对和保真出表；没有真实淘宝发货验收。

登记群读取 ERP 设置 `feishu_shipping_intake_chat_id`，未单独配置时用明确设置的 `feishu_alert_chat_id`。只接受经过飞书验证的用户事件。测试和未启用发货期间仅登记。真正向淘宝提交时要求 `feishu_shipping_operator_ids` 中有当前发送人 open_id，以逗号分隔。

淘宝适配器使用卖家授权的 TOP 应用。启用前在受控运行环境配置 PANSE_TOP_APP_KEY、PANSE_TOP_APP_SECRET、PANSE_TOP_SELLER_SESSION、PANSE_TOP_SELLER_NICK、PANSE_TOP_ERP_SHOP，并核实实际店铺对 trade.fullinfo.get、logistics.companies.get、logistics.offline.send、logistics.orders.detail.get 的权限。PANSE_TOP_SHIPPING_ENABLED=1 启用；默认关闭。凭据由运维通过原有密钥通道配置。关闭期间收到的登记不会事后批量补发。

仅整单单件单包执行一次。先核对本地单、真实平台卖家与子单、退款状态和承运商，再持久占用主单和运单并提交。平台未返回或状态未知时只读核对；仅匹配实际平台物流记录才显示已确认。ERP订单状态仍按官方报表更新。
