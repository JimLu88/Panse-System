# 个人支付宝售后打款联动（2026-09-01）

## 结论

个人支付宝流水是原始付款事实，`after_sales_payment_links` 是唯一的归属关系账。
确认归属后，系统按用途进入两个明确去向：客户差价、返现、赔付、维修、返厂进入一条
受托管售后记录；正常“送装/直达”进入订单安装费。财务、数据大盘、报表和逐单核对
都从关系账及对应权威字段派生，不把同一笔金额复制到五套互不相认的数据里。

历史截图不能单独证明一笔款就是退款。正数收回款、正常送装费、维修费、返厂费、混合用途
款项和可能已在万师傅记账的款项都必须先留在待核对区。系统只允许“明确差价/好评返现/
客户补偿 + 唯一未取消订单”的新流水无人值守入账。

## 五个模块怎样联动

| 模块 | 权威来源 | 确认后的变化 |
| --- | --- | --- |
| 财务流水 | `alipay_flows` | 原流水不改金额；只把核对状态标成已匹配并保留原备注 |
| 售后 | `after_sales_payment_links` -> `after_sales` | 差价、返现、赔付、维修、返厂建立可审计售后关系 |
| 正常送装 | `after_sales_payment_links` -> `orders.install_fee/actual_install` | 送装、直达进入订单安装费，不伪装成二次维修费 |
| 数据大盘和报表 | `after_sales` 的统一成本口径 | 平台内成本加平台外总成本；已有总额时不再重复加明细 |
| 逐单核对 | 订单号关联的售后明细 | 按订单汇总额外售后成本，不把个人支付宝支出伪装成平台退款 |
| 万师傅 | 关联账可选 `wanshifu_order_id` | 只保存关系供防重与核对，不自动改万师傅账单或重复记成本 |

平台退款继续留在订单的 `refund_amount`，个人支付宝打款记作平台外售后成本。两者不能互相覆盖。

## 自动匹配规则

1. 只处理“主力号”的负数支出；正数收入绝不建立售后支出。
2. 备注里的 19 位订单号必须在 ERP 订单库真实存在。
3. 只写客户姓名时，必须精确命中一个未取消订单，并限制在付款日前 400 天内。
4. 同名多单、只有取消单、订单库缺单，一律不自动确认。
5. “送装/直达”建议进入订单安装费；维修、返厂、拆板返进入售后。它们都可能被万师傅
   或其他渠道记过，因此一律先进入待核对，不能自动确认。
6. 万师傅存在候选时，一律进入待核对，防止重复扣成本。
7. 每条确认都带版本号和金额上限；重复请求不会重复入账，过期页面不能覆盖新决定。
8. 错误决定只能作废，不能删除历史。作废会撤回系统托管售后金额或订单安装费，并恢复
   流水原核对状态；若安装费已被其他来源改动，则停止自动回撤，避免覆盖人工数据。

## 历史现场的只读结论

- 本批截图 19 笔全部存在于支付宝原始流水，但上线前仍全部处于未核对状态；“原始账单
  已入库”不能冒充“已经逐单对上”。
- 其中 4 笔明确售后用途可命中唯一有效订单，仍需由正式候选页展示原流水、订单日期、
  产品和金额后再一次确认历史账。
- 另有正常履约/维修类流水能命中订单，但存在万师傅重复成本或业务类型歧义，不能自动确认。
- 其余包括只命中取消订单、订单库缺单、无订单信息、混合用途和同一服务单正反流水。
  系统不能凭备注制造一张不存在的 ERP 订单。
- “送装/直达”不等于退款；它可能是正常履约支出。
- “物流拦截费 +425”是收入，不是售后成本。
- 一笔同时包含客户费用和样品费用的混合款，不能整笔自动挂给一个售后。

## 反方审查与处置

1. **反方：截图都由同事挑出来，全部当退款最快。** 不能接受。截图含正数收入、正常履约、
   混合用途和缺订单记录；全量硬挂会直接做错利润。
2. **反方：客户全名足够可靠。** 只在唯一未取消订单时可靠；同名、复购、取消单必须停。
3. **反方：给财务、售后、报表、订单、万师傅各写一次最直观。** 不能接受。任何一次失败
   都会形成五套余额。采用一条关系账，其他模块派生。
4. **反方：把个人打款写入订单退款金额。** 不能接受。平台退款与个人支付宝售后支出是两种
   事实，混写会重复减少收入。
5. **反方：万师傅有订单映射就自动扣一次。** 不能接受。维修/送装很可能已经在万师傅成本中，
   必须先防重。
6. **反方：自动化就应该零人工。** 自动化不能靠猜。系统将无歧义的新流水自动处理，把少数
   信息不足项集中展示；要进一步消灭人工，必须要求打款备注至少写 ERP 订单号。
7. **反方：历史存量也直接无人值守确认。** 不能接受。旧备注质量不受控，先生成候选再集中确认；
   新流水才按安全规则自动确认。
8. **反方：错误后删除记录即可。** 不能接受。财务变更必须保留责任、时间、原证据和作废轨迹。

上述反方意见均已用“唯一订单、分类白名单、防重、版本锁、金额上限、只作废不删除、单一
关系账”解决。仍无法通过程序消除的只有源数据本身没有订单号或业务性质含糊；此时系统会
明确停在待核对，不会静默做错账。

## 日常使用

- 支付宝导入完成后，系统只扫描本次新入库流水。
- 安全唯一项自动确认；其余项出现在“售后管理 -> 个人支付宝售后待匹配”。
- 历史补账从候选页执行一次只读扫描，再逐条确认或排除。
- 最小化人工的制度要求：个人转账备注统一写 `ERP订单号 + 用途`。客户姓名只能作辅助，
  不能替代订单号。
