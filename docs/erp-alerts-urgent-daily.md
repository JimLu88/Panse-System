# ERP提醒群与紧急订单每日表

用户于2026-11-26确认继续使用交期11天内紧急、5天内非常紧急的规则，提醒发到ERP提醒群，以原工厂表中的独立表展示，不逐单发消息。

提醒群不再发送普通销售日报/周报、备货清单、售后/取数日报、普通数据过期、月度经营简报、月度财务报表、月初数据补录以及旧版通用价保提示。报表计算和任务记录保留。具体活动缺少价保依据、登录扫码、报表口令、订单数量确认、真实业务失败和恢复仍走原有入口；不修改这些消息的授权或去重，也不删除历史群消息。

每天北京时间09:10，原 `daily_urgent_fulfillment` 同时刷新ERP通知中心和工厂多维表格中的 `紧急订单（每日）`。`urgent_fulfillment_feishu_enabled=1` 启用。复用原base绑定，新表ID及创建占位保存于 `urgent_fulfillment_feishu_v1`，原工厂订单表只读。

每个日期、每个主订单一行，附有效子单和工厂单号，从原工厂表精确匹配商品与规格。记录统计日期、紧急程度、目标日期、剩余天数、跟进事项及原因。未匹配的商品明确待核实。每天保留快照，同一天更新原行，退出清单的行改为“已退出今日清单”，不删除历史。员工新增列不覆盖。

已发、取消及全额退款退出；退差价继续提醒并注明退款范围需核实。等通知、延期不自动催发。只有查询和提醒，不发货、不改订单状态、交期、财务或库存。

外部行新增先持久保存记录键，超时后只读核对，未找到原行不盲目重建。整表回读一致后，每天向已配置的ERP提醒群发送一条含日期、数量及表链接的消息；同日不重复发送。无message_id或超时保持待核对，不能清占位重发。字段不匹配时停止，不能改原表结构来绕过。

生产回执位于项目 `outputs/erp-alerts-urgent-20261126`。飞书群历史读取缺少 `im:message.group_msg` 权限，不把程序入口审计当作全部历史消息已审阅。
