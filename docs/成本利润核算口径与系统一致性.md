## 一、标准口径速查(全系统的"基准尺")

| 指标 | 公式 |
|------|------|
| **物理成本** `physical_cost` | 见下「定制单成本决策树」;非定制走定价表 `theoretical_cost`(=`PricingSku.physical_cost`×件数,**已含 物流+安装+打包**) + 实际费用差。**打包与物流/安装一样"差额替换"只算一次**:从 theoretical 派生 estimate_part 时先减嵌入 est_packing,再统一 +packing(2026-06-26 修打包重复,见末尾) |
| **会计成本** `accounting_cost` | 物理成本 + 物流 + 安装上楼 + 额外售后 + 平台扣点 + 税(带双算护栏:theoretical 已含预估物流安装则不再加) |
| **净利** `net_profit` | 实付 − 退款 − 会计成本(逐单) |
| **平台扣点** | 有店铺实收且(实付−实收)≤实付×8% → 实付−实收−退款(真实到账);否则 实付×(手续费0.6%+活动抽成2%) |
| **税** | 本单有 `tax` 用它,否则 实付×2% |
| **活动抽成** | 仅 2026-05-01~06-30 额外加 实付×2%(只 5、6 月有) |
| **成交口径** `settled_sale` | 状态∈(paid/shipped/signed/completed/success/finished) 且 实付>0 且 非全额退款(退款<实付×99%) 且 非¥0纯服务行 |
| **月度净利** | Σ逐单净利 − 推广 − 人员外包 − 固定成本(房租÷12) − 补单(刷单)成本 |

## 二、定制单成本决策树(细则,按优先级)

定制单 = `is_custom=True` 或 SKU 编码带「改」后缀/尾号≥90。成本按以下顺序判定:

1. **补单/刷单** → 成本 0(在补单记录单独核算)。
2. **非产品**(差价/邮费/专链/补拍 + 商家安装/送货等淘宝官方服务)→ 成本 0。
3. **差价单 或 片段单**(备注含"差价/补差价",或 实付 < 整件成本×50%):实付<¥200 → 0;实付≥¥200 → **实付×85%**(留 15% 毛利,挂异常待人工核)。
4. **有工厂账单**(`actual_cost`,工厂账单只含木作):
   - **定制单(用户 2026-06-25 选A)**:base-SKU 定价表非木作不准(定制链接千差万别)→ **物理成本 ≈ 木作账单 ÷ 木作占比**(非木作=木作账单×(1/占比−1),随真实账单等比放大,**不靠定价表**)。木作占比默认**自动取定价表中位**(实测 0.67),可在财务系数 `fin_wood_cost_ratio` 调。**再 85% 兜底**:若工厂账单像零头(账单≪真实,推算后毛利 >30%)→ 退回 **实付×85%**。实测大定制单毛利从乱跳(−6%~27%)收敛到合理 11~24%,且不用逐个补定价表。
   - **非定制单**(定价表准):成本 = 木作账单 + (定价表物理 `theoretical_cost` − 木作 = 配件+物流+安装) + 打包;物流/安装有实际则换实际值。
   - **(c) 片段封顶**:上面算完后,若 实付 < 成本×50%(定金/分期小单)→ 实付×85%。
5. **无工厂账单**(`actual_cost` 空):
   - **(a)** 有定价表/BOM → `theoretical_cost`(物理总成本=商品+物流+安装) + 打包。
   - **(b)** 定制单无任何成本依据 → `custom_order_reconcile` 七级兜底(工厂价 > 定制加价+BOM > 关键词 > 百分比 > 插座数 > 本地 AI > **85%**)写入 `theoretical_cost`(到货填了工厂实际成本即自动覆盖)。
   - **(c)** 完全查不到 SKU/产品成本(如缺产品编码)→ 实付×类目成本率(clamp 0.2~0.95,类目不足退全店)兜底 + 挂「缺成本」异常待人工补。
   - **(d) 推演封顶(用户 2026-06-25 选A)**:上述推演物理成本 **> 实付** 时(多为 追加/差价/凑单 片段,实付只是零头,却匹配了基础产品整件估算成本)→ 按 **实付×85%** 封顶,不背整件成本;工厂账单到了 `actual_cost` 覆盖为准。**仅对全推演单(actual_cost 空)生效;有工厂账单的单以账单为准、不受此规则影响。** 修复前实测 27 单成本>收入中 21 单是这类推演高估(如 ¥550 单背 ¥638)。
6. **件数**:定制/凑价单按 1 件(`_effective_qty`,防"拍N件凑价"的脏 qty 把固定费用×N);真多件(件均实付≥单件成本)才 ×qty。
7. 上面得到物理成本后,**统一**再加 平台扣点 + 税(+ 视双算护栏的物流/安装/售后)= 会计成本。

> 修复记录:2026-06-25 前,4(b) 这类"有木作账单但定价表参照失效"的定制单只补到物流/安装/打包、漏了配件(成本偏低、利润虚高);现已按 max(组件, 实付×85%) 兜底。实测黑胡桃下柜等已纠正。
>
> **修复记录 2026-06-26(打包费重复计算)**:`theoretical_cost = PricingSku.physical_cost × 件数`,而 `physical_cost` **本就含 packaging**(`formula_engine`: physical = 物流+安装+(木作+包装+外采));但 `physical_cost_breakdown` 从 theoretical 派生 `estimate_part` 后**又单独 +packing → 打包算两次**(商品成本虚高、利润被低估)。已修:① 非定制 reconstruct/推演 的 `estimate_part` 先减嵌入 `est_packing`、再统一 +packing 一次(差额替换);② 定制**推演**(theoretical 来自定制报价/兜底,**不含打包**)不减——此前曾误把这类当重复(假阳性),已校正;③ 定制**回填**的木作占比 `_pricing_wood_ratio_median` 分母改 `physical_cost − packaging_cost`(反推不含打包,再 +packing 一次);④ `cost_breakdown` 会计护栏排除定制(定制走占比已隐含物流安装,防潜伏双算)。**物流/安装本就无重复**(差额替换 + 护栏)。生产实测:商品成本降 ¥74,410、利润等额回升,非定制每单正好降 1 份打包(到分验证)。回归 `test_packing_double_fix_0626.py`。**⚠口径**:审计成交单务必用 `is_settled_sale` 且排除补单(=大盘"真实订单"),否则混进关闭/取消单致虚报(真实订单口径降幅实为 ¥47,948)。

## 三、全系统总表(算什么 / 关键规则 / 是否统一)

| 系统 | 文件 | 算什么 | 是否用标准口径 |
|------|------|--------|----------------|
| **财务核心(基准)** | `order_financials` | 物理/会计/净利/扣点/税/成交/补单/区间成本 | **基准** |
| **月度经营·大盘** | `dashboard_monthly_service` / `financial_report_service` / `reports._business_month` | 月营收/成本/利润/资产 | ✅ aligned(全委托基准) |
| **逐单核对(主单核算)** | `reports.per_order_reconcile` + `order_financials` | 每单成本拆解+净利 | ✅ aligned |
| **销售汇总/排行** | `sales_analytics`(summary/breakdown/ranking) | 营收/成本/净利/毛利/利润率 | ✅ aligned(主路径) |
| 销售日汇总 rollup | `sales_rollup_service` | 逐日预聚合 | ⚠ diverges(net_profit 缺平台费/税/售后)——**但无前端消费,休眠**(已加告警) |
| **成本反推/回填** | `order_cost_service` / `order_fee_actual_service` | theoretical_cost/片段/件数/兜底 | partial(供给端,写 theoretical;口径与基准对齐) |
| **财务对账** | `reconciliation_service` / `order_reconciliation_service` / `settlement_import_service` | 应到账 vs 支付宝实到账 差额 | partial:**是现金到账核对,不算利润**,不冲突但命名易误读 |
| 定制单对账 | `custom_order_reconcile_service` | 定制成本推断(7级)写 theoretical | 设计内兜底(无账单时填推演,账单到即覆盖) |
| **工厂对账单** | `factory_reconciliation` / `factory_recon` / `factory_recon_import` | 账单 Σ ↔ 付款 现金核对;Σ结算价回填 actual_cost | partial:利润零自算全交基准;回填已修为覆盖重算(防分批丢) |
| **定价/报价** | `pricing_calc` / `formula_engine`(定价表) | 标价/日常价/大促/会计成本/毛利率 | 与会计口径**同构**(物理+平台费+税),数值可还原 |
| 定制报价引擎 | `custom_quote_v2` / `custom_quote_service` / `smart_pricing` | 锚点插值+材质/尺寸/部位 delta(事前报价) | partial:自实现级联,不调标准函数(事前估,非事后核算) |
| **现金流/资产/ROI** | `cash_flow_service` / `asset_service` / `roi_service` | 现金/资产/推广ROI | partial→已修(见下) |

## 四、一致性结论

**主链已统一** ✅:你看到的所有利润数字(月度经营、大盘、逐单核对、销售排行、现金流总利润、资产公式B)都委托同一个 `order_financials`,口径一致、数字可信。**不存在"某系统用不同口径算你看到的利润"。**

**2026-06-25 已修的分歧:**
- **定制单缺配件**(4b)→ max(组件, 实付×85%)。已部署 `675dd77`。
- **ROI `compute()`** 营收 改为 实付−退款(原只 Σ实付,虚高)。已部署。
- **工厂账单回填** 改"仅填空"为覆盖重算该单全部批次 Σ(防分批开票第2批静默丢失;当前0分批单,属预防)。已部署。
- **rollup** 加告警注释(毛估、勿喂 P&L)。已部署。

**剩余(低优,文档/休眠级,不影响显示数字):**
- 对账系统字段命名(`expected_net`=应付−税−平台费)宜与"利润"解耦,防误读(纯命名)。
- rollup 预聚合若将来要喂 P&L,必须先补平台费+税+售后(现休眠)。
- 定制报价引擎与事后核算同构但不共用函数(事前/事后分离,可还原,低优)。

## 五、改动注意
- `physical_cost` 实时计算 → 改它部署即全盘生效,无需重算。
- `theoretical_cost`/预估三费 存库 → 改逻辑后要跑 `auto_cost_backfill` / `sync_fee_components`。
- 定制单绝不可整柜 `recompute_and_save`(会把定金单赋整柜成本)。
- 工厂账单只含木作;非木作(配件/物流/安装/打包)由 physical_cost 按定价表参照补,或 85% 兜底。
