# 工厂订单表字段更新合同

适用：畔色工厂订单 → 订单管理（tblqn9PDPO0S69wZ）→ 订单管理表（vewaQAjTUH）。
用户2026-09-09要求所有可核验系统字段持续更新。ERP单向投影，不反向修改订单。
生产调度仍为每360分钟，另有订单收口同步；旧任务ID feishu_sync_30min 不代表30分钟。

## 字段矩阵

下列均为已有系统管理列；不在表内的工厂人工列一律不写。允许工厂改视图名称/列顺序，
日常同步不再迁移字段、变更字段类型、删除列或记录。来源缺失不是清空授权。

| 字段 | 权威来源及父子语义 | 更新及空值规则 |
|---|---|---|
| 工厂下单号 | 子订单factory_no；无导入子行才用父单编号/远期号 | 精确实体原位更新；缺号保留旧值，不跨号猜匹配 |
| 订单号 | 父订单order_no | 不可变关联键，重复键阻断写入 |
| 子订单号 | 导入明细sub_order_no | 精确关联；旧主单只有主单+工厂号唯一一致才原位升级 |
| 商品名称 | 子行商品名→精确SKU定价表；旧父单产品档案 | 有来源才覆盖，空缺保留 |
| 产品编码 | 子行→精确SKU定价表；无子行用父单 | 空缺保留，不从其他商品推断 |
| SKU编码 | 子行sku_code；无子行用父单 | 空缺保留 |
| SKU规格 | 子行sku_name→精确SKU定价表sku | 订单快照有值按快照更新；快照缺失时定价表只补远端空格，不能覆盖既有订单/工厂规格；未知保留 |
| 尺寸 | 精确SKU定价表size_info | 缺失不清空 |
| 订购数量 | 子行数量；沿用既有定制凑价生产数量口径 | 正常更新；多子不能用父总数代替 |
| 木作成本价 | 普通精确SKU木作价；单子定制复用订单核价；旧父单原成本路径 | 未知不写零、不清旧值；多子不分摊父总成本 |
| 定制标识 | 子行SKU/精确定价/单子标识，父单仅无子或唯一实体 | 不把兄弟定制身份传播到普通子SKU |

| 订单状态 | 可靠子状态优先；无子行才父状态 | paid→生产中/待制单；shipped→已发货；signed→已签收；未知待核实；超期不算发货 |
| 交期紧急度 | 同一子状态+父单客户交期规则 | 已发货/签收为完成；售后单为售后处理；进行中按交期 |

| 客户延期单 | 父单明确延期标识 | true/false均更新 |
| 客户通知拍照 | 父单明确备注含否定词消解规则 | true/false均更新；不以已上传图片反推已发货 |
| 订单提醒 | 延期和拍照标识组合 | 依据消失可清除旧系统提醒 |
| 订单备注 | ERP买家/卖家/ERP/生产备注 | ERP来源删除可清空；不覆盖独立工厂人工备注列 |
| 客户名称 | 父单现有合法客户字段 | 已知更新；缺失保留；回执不含值 |
| 客户联系方式 | 父单电话文本（含非标准号码） | 不转换号码；缺失保留；回执不含值 |
| 客户地址 | 父单现有合法地址 | 已知更新；缺失保留；回执不含值 |

| 工厂下单图 | 同实体已实际发送、工厂号一致的最终图签名 | 复用签名；缺失/上传失败不清图；新图追加并保留原附件，不自动删除工厂图片 |
| 系统更新时间 | 实际差异写入时的上海时间 | 没有业务变化不刷新；不能用此时间代替最近调度时间 |

## 终态、冲突和保护

- 退款/取消：只对ERP精确证明失效的实体标记已作废、取消、暂勿发货；保留记录/人工列/附件。
- 小额已完成退款不自动作废商品；退款中是售后核实，不冒称全部退款完成。
- 父paid/子signed按子已签收；多子一签收、一未发货分别保留。未知子状态不借父终态升级。
- 392/379/360在本轮源数据paid且无发货证据时仍生产中。139采用真实工厂号与实时子键，不猜截图转录键。
- 飞书有而ERP未匹配的行全部保留，不仅保护此前2行；有旧主单但实体映射不清时不另建重复行。
- 只更新明确变化的系统列，保留其他列；未知成本/规格/附件在回执统计，不宣称全部数据已齐。
- 定时/订单收口/手动共享进程锁与PostgreSQL事务级锁；忙时返回明确失败，不能并发重放。
- 批次失败和写后差异均返回ok=false进入既有失败链；无盲目重试。缺图片允许核心字段更新，但另列未决数。

## 正式操作与验收

02测试并部署后，01唯一执行：容器内 `python -m app.cli.factory_dispatch_audit` 是只读GET差异预览，
`python -m app.cli.factory_dispatch_audit --apply-table tblqn9PDPO0S69wZ` 执行一次本表正常同步。
默认预览启用数据库READ ONLY，不上传附件、不迁移字段、不提交数据库，不发送消息。
原POST /api/orders/factory-dispatch/sync仍使用同一受控同步函数。

回执field_changes是计划字段差异数；verified_field_changes是写后回读确认的变更字段数；
remaining_field_differences是剩余不一致，不能把HTTP成功当完成。新建行另以created与读回结果计。
最后再运行只读预览核对全部可核验系统列，已更新列应无差异；无法确定的来源单列未决原因。
源订单/子行最后更新时间只说明已有数据新近程度，不证明淘宝无新增订单；订单拉取失败仍由原收口/数据新鲜度监测报警。
本合同不修复淘宝源数据、不改报价、不发短信、不新增日程，也不开放其他表权限。
