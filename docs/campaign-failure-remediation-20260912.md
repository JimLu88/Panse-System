# 四类失败自动处理（用户2026-09-12直接确认）

本补充落实既定连续报名合同，不修改旧请求/价格版本/凭证的SHA，不恢复预检。
日常任务只调用已固化Web Agent；AI不临时点击、填写、导出或上传。

1. 本场官方明确动销不达标：本场不再报名，也不为它处理价格。下场仍全量尝试。
2. SKU不属于商品或已下架：固定录屏流程完整导出全部出售中商品，核对总数、页数、
   文件覆盖、商品ID/SKU ID和唯一ERP编码。没有对应/已明确不支持报名的SKU从
   本次失败商品的报名SKU集合去除，不删除淘宝SKU、不改库存或上架开关。其他SKU
   保持全量；歧义和导出失败只拦对应商品，其余继续。不能把零库存当下架。
   同一连续任务没有商品编辑/轮换时，复用已完整验证的本轮导出；每次只校验原作业、
   文件与范围，不重复下载。改变商品后进入新快照上下文，不能继续复用旧清单。
   多批次明确无效的SKU累计取并集，不得下一轮重新带回。已登记备用SKU的商家编码
   别名按原创建/保存回读及当前导出精确对应，不得凭B1/B2后缀自行推断。
3. 定制价格：按官方限制直接求可行报名价，保护已建立的固定原价×20%，不再询问
   已授权的底线内降价。平台“需小于”上限取上限减0.01元；20%底线向上取到分。
   低于底线才列入轮换待确认；缺基线不编造，也不误判一定轮换。
4. 普通SKU历史价/券后价：报名价等于ERP日常价。相对固定ERP目标最终价±2元
   （含2元）以内自动原位修正本场立减；超过2元列入轮换待确认，不自动轮换。
   每轮不重新让2元，不能新增优惠叠加。定制先按第3项处理。

固定顺序：解析报告→分类→必要时一次完整录屏导出并核对→自动修复→生成失败商品
完整合格SKU集合→复用成功优惠/读回精确窗口→补报→新批次终态和报告。
成功或未知结果不重放；修改无效果不反复提交。轮换仍需用户当前确认。
独立反馈取回通过固定recover-signup-report接回原report断点，不改原signup终态。
下载回执、原始报告、采样录像和本地测试不等于报名成功。

## 部分导入与小额价格差的固定接续

- 单品立减部分成功时，必须以原失败文件、全部成功SKU原位读回、相同活动与窗口互相
  核对。只复用“原提交集合减明确失败集合”的精确物理SKU；商品级未知状态不改为成功。
  本场明确无效SKU仅从后续文件剔除，不把新物理SKU推断为已成功优惠，也不重传268条。
- 平台展示券后价与ERP计算差几角钱时，不猜测优惠来源。只有计算值及平台各观察值、
  本次修正前后都在同一ERP目标价2元内，才自动使用满足所有已知上限的最小修正。
  任何口径越界或证据不足仍隔离；不把每次修改当成新的2元额度。
- 原位修改在进入页面前失败，只有原job、尚未消耗的claim、明确的绑定前错误、没有
  操作/录屏文件全部成立时，固定恢复入口才允许继续同一job一次。不重建claim、不解除
  已派发锁；真正结果未知只能读回。成功保存的原job由固定读回接续原repair断点。
- 已核验的备用SKU编码补充采用新回执，原映射、创建目标、保存证明及本轮官方导出
  精确绑定，不修改原已登记回执，不按后缀猜测，不改变ERP价格版本。
