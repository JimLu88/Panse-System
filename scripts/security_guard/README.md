# 群晖轻量安全监测

2026-11-12 用户最终范围：保留每小时异常检查、每日安全检查、飞书去重提醒。
Windows 每5分钟外部ERP检查已取消；Antivirus更新、扫描、等待器保持停止，不得自动恢复。

## 运行

NAS `/volume1/docker/panse/security-guard/nas_guard.py`：

- `hourly`：每小时第05分钟，读取最多6000个进程的短命令行、进程计数、15分钟负载和内存；核查已停Plex/杀毒是否意外启动、23/32400/32402是否重新监听。
- `daily`：每天08:20，仅核查明确列出的启动配置、账号、代理配置、Plex代码缓存/插件目录。上限500文件、深度5、内容读取8MiB；单文件超过1MiB只比对大小/时间/权限。达到上限或读取失败明确报告覆盖不完整。
- `baseline`：只允许首次人工建立；绝不自动接受后续变化。基线代表审核起点，不代表整台NAS无恶意文件。
- `audit`：只读取监测结果的新鲜度及未知发送状态，每日由Codex执行一次自检。不是ERP外部可用性检查，不产生额外飞书发送。
- `commission`：一次启用通知。持久去重，重复执行不重发。

不扫描电影/照片/订单/数据库，不运行安全顾问密码扫描，不安装更新，不删除、隔离或重启任何业务程序。

## 资源与通知

systemd oneshot service：Nice19、CPUQuota10%（单核比例）、MemoryLimit64MiB、空闲磁盘IO优先级；每次最多90秒，超时结束。本地采集不创建常驻进程。只有新通知才通过现有ERP API容器中的飞书客户端发送；该短通知进程受原容器约束，不冒称其受采集器64MiB限制。

本地SQLite记录事件及发送意图，发送前落盘。只有真实 `om_` message_id算送达。失败/超时/崩溃后未知发送不自动重试，不改用其他渠道；每日自检报告新增未知状态。同一故障只发送一次；已成功发送的故障恢复通知一次，重新发生使用新episode。每日至多12份、每份最多12项/8000字节；23:00—07:00普通提醒延后，明确高风险进程等严重异常可直接发送。

NAS完全离线或ERP通知容器不可用时，这个NAS内的通道不能独立报警；用户已取消Windows外部探测。Codex每日自检依赖电脑开机、应用运行，不能宣称为24小时云端掉线监控。

## 维护与停止

只更新独立脚本和`panse-security-hourly`/`panse-security-daily`两个service/timer，不变更ERP镜像或数据；部署持有既有NAS release lock。
停止：`systemctl disable --now panse-security-hourly.timer panse-security-daily.timer`，并通过Codex自动任务接口暂停每日自检。保留状态与回执。

`test_guard.py`验证去重、恢复、再次发生、未知发送不重试、安静时段、每日限额和作用域隔离。生产验收需实际读取timer、资源限制、首轮耗时/CPU/内存及飞书真实回执。
