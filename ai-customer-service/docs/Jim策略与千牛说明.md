# Jim 策略拆分与千牛侧能力说明

## 1. 询价/拍下 vs 实拍（两个独立开关）

控制台「主理人业务策略」中：

| 主开关 | 子开关（完整 Jim） | 含义 |
|--------|-------------------|------|
| **涉及报价、发单、改价…转人工** | **询价/拍下命中后走「完整 Jim」** | 打开主开关且命中询价/拍下意图时：若子开关**开**→ 发安抚话术 + `ManualHold`（与旧版一致）；子开关**关**→ **仅推送**（已配置 Server酱 / PushPlus / 企微 / 宿主机 HTTP 时）+ 会话事件 + HITL 记录，**不发安抚、不设 ManualHold**，自动接待可继续。 |
| **客户要实拍/细节图时转人工** | **实拍命中后走「完整 Jim」** | 同上，针对实拍/细节图意图。主开关关时子开关灰显。 |

两条分支**同时命中**时：仅当**两个**子开关都要求「完整 Jim」时，才执行完整接管；任一为「仅推送」，则整次按「仅推送」处理（避免一条消息里一半锁会话一半不锁）。

数据库字段：`policy_settings.jim_price_full_takeover`、`jim_photo_full_takeover`（`1`=完整，`0`=仅推送）。

## 2. 千牛「标记已读」自动化

当前千牛客服工作台 **未提供稳定、可长期维护的「标记已读」公开 API** 供本机 UIA 方案可靠调用；若强行模拟点击，易随千牛版本失效且易误点。

**结论（产品行为）**：本版本 **不做** 自动「标记已读」。若业务上需要「不打扰客户、仅自己已读」，请在店内流程中约定由人工在千牛内处理，或接受「仅推送 / 跳过自动回复」类策略由本系统其它路径完成。

若未来接入官方/稳定接口，可在驱动层单独扩展，不与现有 Jim 策略耦合。
